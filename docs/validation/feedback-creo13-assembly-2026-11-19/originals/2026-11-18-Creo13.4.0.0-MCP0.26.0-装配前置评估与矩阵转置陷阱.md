**环境**：Creo 13.4.0.0 · MCP_CREO_MechDog 0.26.0 · Windows
**评估对象**：液压缸 9 件（已建成，体积偏差合计 +0.0025%）的装配落地可行性

## 三、源码级硬事实与定量影响

### 3.1 矩阵约定：MCP 是行向量，且**明确声明不转置**

```python
# src/creo_mechdog/schema.py:98-99
ROTATION_CONVENTION = "row_vectors_local_to_parent"
ROTATION_FORMULA = "p_parent = p_local * rotation_matrix + translation"
```

`schema.py:121-127` 的字段说明进一步写明：

> "Row-vector local-to-parent rotation: p_parent = p_local * rotation_matrix + translation
> (p_local is a row vector; the matrix is **not** a column-vector transpose). ... The values are
> applied exactly as given: **never transposed**, orthonormalized or repaired."

也就是说：MCP **不做任何自动转置**。而建模说明书 8.2 的约定是列向量 `P_装配 = R·P_局部 + T`。

**两者差一次转置，必须由调用方完成**：`rotation_matrix = Rᵀ`。

数学上验证：行向量 `p · Rᵀ = (R · pᵀ)ᵀ`，正是列向量写法 `R·p` 的等价形式。**传 Rᵀ 才对，传 R 是错的。**

### 3.2 定量影响：7/9 件转置前后完全相同

用 9 件真实局部质心逐件计算"传 Rᵀ"与"传 R"的装配位姿差：

| 件 | R 是否对称 | det(R) | 传 Rᵀ（正确）位姿 | 传 R（错）位姿 | 最大差 |
|---|---|---|---|---|---|
| P01 缸体 | 是 | +1.0000 | (0, 0, 178.941) | 同左 | 0.000 |
| P02 活塞杆 | 是 | +1.0000 | (0, 0, 545.920) | 同左 | 0.000 |
| P03 活塞 | 是 | +1.0000 | (0, 0, 321.334) | 同左 | 0.000 |
| P04 活塞盖 | **否** | +1.0000 | (0, 0, 368.712) | 同左 | 0.000 |
| **P05 缸筒盖** | **否** | +1.0000 | (0, 0, 382.871) | (0, **−10.691**, 386.038) | **10.691** |
| P06 前盖 | 是 | +1.0000 | (−1.307, −0.007, 424.218) | 同左 | 0.000 |
| P07 前耳环 | 是 | +1.0000 | (0.419, 0, 854.966) | 同左 | 0.000 |
| P08 后耳环 | 是 | +1.0000 | (−0.577, 0, −112.370) | 同左 | 0.000 |
| **P09 端盖** | **否** | +1.0000 | (−1.920, 0.359, −19.996) | (1.920, −0.359, −19.996) | **3.841** |

**要点（比说明书自己的记录更严格）**：

- R 为对称阵的有 **6 件**：P01、P02、P03、P06、P07、P08。
- **P04 活塞盖的 R 不是对称阵，但它的局部质心 (0, 0, 19.212) 落在旋转轴上**，绕轴旋转不改变质心位置，所以**转置错误在它身上同样看不出来**。
- 因此"靠抽查单件质心"能暴露错误的**只有 P05、P09 两件**，容错率 = 2/9。
- `det(R) ≡ +1.0000`，**det 检验永远发现不了转置错误**（`det(Rᵀ) = det(R)`）。

### 3.3 说明书自带判据的漏洞：只看 cx 会漏判

按 9 件局部质心与体积计算装配体总质心（未赋材料，等密度）：

| 写法 | 总质心 (x, y, z) | 与说明书正确值对比 |
|---|---|---|
| **传 Rᵀ（正确）** | **(−0.380, +0.032, +324.470)** | ✔ 与说明书 (−0.379, 0.032, 324.467) 吻合到 0.003 mm |
| 传 R（转置错） | (−0.026, **−0.605**, +324.639) | ✔ 与说明书"全转置实测" (−0.026, −0.556, 324.606) 同量级吻合 |
| 两者之差 | Δx = **0.354**，Δy = **0.637** | — |

**问题在于**：说明书第三条硬断言只写了"cx = −0.379 ±0.5 mm"。
错误装配的 cx = −0.026，`|−0.026 − (−0.379)| = 0.354 < 0.5` → **通过**。

> **建议把判据改为三轴同时约束**：`cx = −0.379 ±0.5`、`cy = +0.032 ±0.5`、`cz = +324.467 ±0.5`。
> 其中 **cy 是唯一能抓住转置错误的单一数字**（偏差 0.637 > 0.5）。

**P05 包围盒（最硬的判据）**：

| 写法 | x 范围 | y 范围 | z 范围 |
|---|---|---|---|
| 传 Rᵀ（正确） | −100.29 … +100.29 | −100.29 … +100.29 | **352.50 … 402.50** |
| 传 R（错） | −72.50 … +72.50 | −88.04 … +60.80 | **321.08 … 441.99** |

与说明书实测错值（z 321.09…441.98、y −88.04…60.81）**逐位吻合**，说明本复算模型可信。
错的时候 Ø145 的盘被转成"侧立"，一眼可辨；而体积 5,780,637.3 mm³ 分毫不变 —— **体积不能当验收**。

### 3.4 6 位小数矩阵触发 1e-6 正交门槛（新发现）

`schema.py:129-133`：`rotation_tolerance` 默认 **1e-6**，校验 `R·Rᵀ = I` 且 `det = +1`。
模拟说明书 8.2 给出的 6 位小数矩阵：

| 件 | max\|RRᵀ − I\| | \|det − 1\| | 默认 1e-6 门槛 |
|---|---|---|---|
| P01 / P02 / P06 / P07 / P08 / P09 | 0 | 0 | 通过 |
| P03 活塞 | **1.046e-06** | **1.046e-06** | **不通过** |
| P04 活塞盖 | 2.093e-07 | 2.093e-07 | 通过 |
| P05 缸筒盖 | 6.866e-07 | 6.866e-07 | 通过（余量仅 1.5 倍） |

**P03 活塞会直接被准入校验拒绝**，报错文本见 `schema.py:72-78`：

> "rotation_matrix must be orthogonal within 1e-6 ... so supply exact orthonormal values, or pass an explicit rotation_tolerance to ..."

**处置**：对 P03 显式传 `rotation_tolerance: 1e-5`（合法，且文档说明"admits a documented rounded matrix without repairing it"）。
**建议**：把实测残差直接写进报错文本（现在只说门槛是多少，不说你差多少），否则调用方要自己算；或把默认值放宽到 1e-5（6 位小数的矩阵天然会有 1e-6 量级误差，1e-6 门槛与常见数据精度不匹配）。

### 3.5 `fixed` 与 `constraints` 是互斥分支，不是叠加

```cpp
// native/advanced.cpp:2383-2385
if (placement == "fixed")
    fix_component(&comp);                       // 约束表 = [PRO_ASM_FIX]
else if (placement == "constraints")
    component_constraints(&comp, op["constraints"]);   // 约束表 = 你给的列表
else
    ... PRO_ASM_DEF_PLACEMENT                   // 约束表 = [PRO_ASM_DEF_PLACEMENT]
```

`fix_component` 写入的是**只有一条 FIX 的列表**（`:2093-2100`），`component_constraints` 写入的是**另一个全新分配的列表**（`:2251-2299`），最后统一走：

```cpp
// native/advanced.cpp:2298
ProError e = ProAsmcompConstraintsSet(nullptr, c, list);   // 整体设置，不是追加
```

**推论（关键）**：

1. 同一个 `assemble_component` 里，要么 fixed、要么 constraints，**无法两者共存**。
2. 分两步做也没用：先 `placement=fixed` 插入，再调 `creo_component_constraints`，它会用新列表**整体覆盖**，`PRO_ASM_FIX` 被删除 → 组件从"固定"变成"由配合驱动"，位置改由求解器决定。
3. 因此说明书 8.5 那句"9 件全部设为 fixed 后再补 22 条配合，CAD 会接受（过定义但可解）"是 **SolidWorks 的行为**，在 Creo 这条 MCP 路径上**不成立**。

`capabilities.py:722-728` 的 `placement_semantics` 也印证了顺序：

> "a constrained component is **inserted fixed and then its constraints are set**"

——插入时先临时 fixed，随后 set，set 的结果就是 FIX 被替换。**净效果 = 无固定。**

### 3.6 约束类型的真实接受范围

`schema.py:1970-1985`：`mate` / `align` / `insert` / `csys` **不接受 offset**，带偏移直接抛错；需要偏移必须用 `mate_offset` / `align_offset`。

`assembly_constraints.py:50-51`：

```python
FACE_REFERENCE_KINDS  = {"surface", "plane", "datum_plane", "datum_feature", "geometry_selector"}
COAXIAL_REFERENCE_KINDS = {"surface", "geometry_selector"}
```

- `coincident → mate`：可收面 / 基准面（平面性由原生侧解析后再校验，`:66-80`）。
- `concentric → insert`：**只收 `surface` 或 `geometry_selector`**；传 `axis` / `edge` 会被拒。`geometry_selector` 形式还**必须带 `radius_mm`**（`:70-78`），否则可能解析到平面。

## 五、过约束风险（比 API 缺口更现实）

Creo 与 SolidWorks 在冗余约束上的行为不同：SW 接受"过定义但可解"，Creo 通常**直接拒绝**重复/冲突约束。当前清单里：

| 组合 | 条数 | 判断 |
|---|---|---|
| 缸体 ↔ 缸筒盖 | 3 条 `mate` | 同一对平面用 3 条 mate 定死，**大概率被判冗余** |
| 活塞杆 ↔ 活塞 | 2 条 `mate` | 同上 |
| 活塞杆 ↔ 前耳环 | 2 条 `mate` | 同上 |
| 前耳环 ↔ 后耳环 | 4 条 `mate` | 两件**物理不接触**，且应改为 `insert`（轴线对齐） |

**建议做法**：不要"一把梭 22 条"。按语义去重后提交 —— 每对零件只保留**刚好定死自由度**的最少约束：
同轴用 `insert`（1 条/对），端面贴合用 `mate`（1 条/对），需要留间隙用 `mate_offset`。
去重后大约 **10~12 条**，反而更容易通过，也更能说明"关系正确"。

## 六、给 MCP 的改进建议（按优先级）

### P0 —— 直接影响能不能用

**P0-1 提供"固定 + 追加约束"的写入模式**
现状：`placement` 是 if/else 互斥分支（`advanced.cpp:2383-2385`），`component_constraints` 整体覆盖（`:2298` `ProAsmcompConstraintsSet`）。
需求：新增 `keep_fixed: true` 或 `constraint_mode: "append"`，在 App 层"读出既有约束列表 → 追加 → 回写"。没有这条，**"精确位姿 + 关系证据"在 Creo 上无法共存**，用户只能在两者中二选一。

**P0-2 `rotation_matrix` 支持显式声明列向量约定**
现状：只按行向量解释，且明确不转置（`schema.py:98-99, 121-127`）。
需求：新增 `rotation_convention: "row" | "column"`（默认 `row` 保持向后兼容），`column` 时内部转置一次。
理由：**这个错误 7/9 件查不出来**（§3.2），每个调用方自己写一遍转置必然出事 —— 本项目此前就已在 SolidWorks 侧踩过同一个坑。

**P0-3 把实测残差写进正交校验的报错**
现状：报错只说门槛是 1e-6（`schema.py:72-78`），不说调用方差多少。
需求：message 里加 `measured residual = 1.046e-06, suggested rotation_tolerance = 1.0e-05`。
理由：P03 就是这样被拦下的（§3.4），而 6 位小数的合法旋转矩阵天然会超 1e-6。

### P1 —— 影响效率与可信度

**P1-1 公布 `parallel` / `distance` 的替代映射表**
在 `capabilities` 里直接写"parallel → align、face distance → mate_offset"，并注明轴线/点距离**无替代**。现在只在源码注释里说（`assembly_constraints.py:37-48`），调用方看不到。

**P1-2 约束失败要给出"第几条 + 原因"**
现状：`status=6` / `code=-1`。需求：`failed_constraint_index`、`failed_constraint_type`、`reason ∈ {redundant, inconsistent, tangent, radius_mismatch, unsupported_surface_kind, self_reference}`。`component_constraints` 是整批写入，一条错全批失败，没有序号等于盲猜。

**P1-3 `inspect_session_assembly` 增加逐组件世界包围盒**
需求：每个 component 返回 `bbox_min/bbox_max`（装配坐标系）。
理由：**包围盒是唯一与矩阵写法、行列顺序、软件约定都无关的验收判据**（§3.3 实测：正确 z 352.50…402.50 vs 错误 321.08…441.99）。现在只能拿到 4×4 变换，无法独立验收 —— 相当于让调用方"用自己的错误去验证自己的错误"。

**P1-4 `inspect_model` 的 surfaces 段返回面积**
现状：只有 bbox/origin/radius（P06 排查时已遇到，见 2026-11-18 的 P06 文档 P-02）。装配阶段的贴合面判据同样依赖面积。
