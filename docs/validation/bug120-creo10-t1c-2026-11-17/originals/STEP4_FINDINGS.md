# T1-C 第 4 步：中间截面是否真的起作用（实机）

日期：2026-11-17　模型：`T1C_MID`（新件，`model_id=4defc6086f7d4e8485ff4b6a056de6c1`）
只验证**第一方向**，未做第二方向。

---

## 1. 案例构造

三条平行直线，都沿 X，长度 20 mm，间距 20 mm，中间一条抬高 3 mm：

| 截面 | 草图 | 位置 | 曲线几何 ID | 所属特征 |
| --- | --- | --- | --- | --- |
| END_A | `END_A_SEC` | y=0, z=0 | 51 | 48 |
| MID | `MID_SEC` | y=20, **z=3** | 45 | 42 |
| END_B | `END_B_SEC` | y=40, z=0 | 57 | 54 |

**创建次序与空间次序故意不同**：

- 实际创建顺序：`MID_SEC`（revision 1→2）→ `END_A_SEC`（2→3）→ `END_B_SEC`（3→4）
- 空间顺序：END_A → MID → END_B
- 驱动请求按**空间顺序**给出：51 → 45 → 57

三个草图均为 `dimensioning=coordinates`，几何偏差 ≤ 1e-63 mm，`sketch_shifted.detected=false`，
即线就在要求的位置上，不是解算挪过去的。

## 2. 顺序：父引用不能当顺序证据（本次实测坐实）

四个混合特征（60/72/84/96）的父引用**全部**为 `[42, 48, 54]`：

```
60 parents [42, 48, 54]   72 parents [42, 48, 54]
84 parents [42, 48, 54]   96 parents [42, 48, 54]
```

而请求顺序对应的特征是 48 → 42 → 54。父引用是**按 id 升序的集合**，与采集顺序无关。
这正面证实了任务书里的那句话：父引用只能作为依赖集合证据。

---

## 3. 真正的顺序观察：曲面参数方向

对 `边界混合 1`（quilt 66，feature 60）做参数探针，u、v 各自归一化到 0..1：

| (u, v) | xyz (mm) | 含义 |
| --- | --- | --- |
| (0.0, 0.0) | (0.0000, 0.0000, 0.0000) | A 起点 |
| (0.0, 0.5) | (10.0000, 0.0000, 0.0000) | A 中点 |
| (0.0, 1.0) | (20.0000, 0.0000, 0.0000) | A 终点 |
| (0.5, 0.0) | (-0.0000, 20.0000, **3.0000**) | **中截面**起点 |
| (0.5, 0.5) | (10.0000, 20.0000, **3.0000**) | **中截面**中点 |
| (0.5, 1.0) | (20.0000, 20.0000, **3.0000**) | **中截面**终点 |
| (1.0, 0.0) | (0.0000, 40.0000, 0.0000) | B 起点 |
| (1.0, 1.0) | (20.0000, 40.0000, 0.0000) | B 终点 |

- **u 是跨截面方向，v 是沿曲线方向**（v 从 0 到 1，x 从 0 走到 20）。
- u 从 0→0.5→1 依次经过 **A(y=0) → 中(y=20,z=3) → B(y=40)**，与请求的空间顺序一致。
- 若采集顺序是创建顺序（中→A→B）或父引用顺序（42,48,54 = 中→A→B），
  那么 u=0 处就该是 z=3 的中间截面。实际 u=0 处 z=0，u=0.5 处才是 z=3。
- 这是几何自身的记录，不是回调返回码，也不是父引用数组。

## 4. 曲面确实经过中间曲线

同一 quilt 的 UV 取样（grid=24，625 点，失败 0）：

- 采样范围 `X∈[0,20]`、`Y∈[0,40]`、`Z∈[0, 3.0000000000000027]`
- 目标点 (10, 20, 3) 的最近采样点 **(9.999999999999993, 19.999999999999964, 3.000000000000001)**，
  距离 **3.62e-14 mm**
- 若中间截面被忽略，曲面会是 z=0 的平面，该距离应为 **3.0 mm**

面积与包围盒（实时查询 `inspection_source=live_query`）：

- quilt 66：面积 **810.7517 mm²**，`face_count=1`，`feature_ids=[60]`
- bbox `[-0.120004800192008, -0.12000480019200767, -0.12000480019200767]` ~
  `[20.120004800192007, 40.12000480019201, 3.120004800192009]`
- 平坦两曲线基线是 800.0 mm²，抬高后 810.75 mm² 是合理的增量；
  bbox 的 **Z 上限 3.1200048** 与第 2 步结论一致：3.0 是真实几何高度，
  多出的 0.12 是 `ProSurfaceDataGet` 的数据结构余量，不是几何。

## 5. 采集器行（没抓到，如实记录）

想直接截下仪表板「第一方向」的链行作为采集器证据，尝试了三次，**都没成功**：

1. 后台跑驱动 + 全屏连拍 6 帧（2 s 间隔）——面板已关闭；
2. 区域连拍 40 帧（200 ms）——全是关闭态；
3. 同进程并发连拍 107 帧（40 ms，覆盖整次运行）——**107 帧逐字节采样差异为 0**，
   说明屏幕抓取拿到的是不刷新的静态层，这个通道在当前会话抓不到短暂出现的面板。

另外两条本想用来取有序记录的途径也不可用：

- `creo_dump_feature_tree`（元素树导出）失败：`ProFeatureElemtreeExtract` 返回 `-18`。
- 想用「第 4 条引用故意失败」把面板卡在开了 3 行的状态：`geom_id=999999` 在
  `prepare` 阶段就被拒（`prepare_failed`），一条都进不去；
  改用**基准面 id 40**（存在、但不是曲线）后 `select` 竟然也返回 0，
  特征照样建成，父引用仍只有 `[42,48,54]`。

由此得到两个必须记下来的结论：

- `reference_not_a_curve` 这个 reason 是**名不副实**的：它实际表示「该 id 解析不到」，
  基准面这种非曲线对象并不会被拒。
- **`ProSelectExternalselectionRecord` 返回 0 不等于这条引用真的进了采集器**——
  必须用几何或特征父引用另行验证，不能只看返回码。

顺序结论最终由第 3 节的参数探针给出，属于几何观察，比截图更硬。
