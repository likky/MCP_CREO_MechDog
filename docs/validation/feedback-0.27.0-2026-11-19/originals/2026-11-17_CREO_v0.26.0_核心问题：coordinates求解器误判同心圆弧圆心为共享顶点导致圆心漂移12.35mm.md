# 2026-11-17 CREO v0.26.0 核心问题：coordinates 草图求解器把同心圆弧圆心判为共享顶点并跳过约束，导致圆心漂移 12.35 mm

> 反馈对象：MCP_CREO_MechDog 作者
> MCP 版本：v0.26.0（源码 `56a2cb8…` / worker `5b01005…`，CREO 9.0 / release 41）
> 复现日期：2026-11-17
> 复现任务：按 TXT 附录 B 的 `SK P01-01` 重建 Part1 环形链板草图（8 段圆弧、2 个闭合环、4 组同心圆弧）

## 1. 问题摘要

`sketch` 操作使用 `dimensioning="coordinates"` 时，原生坐标求解器会把**圆心坐标相同的多个圆弧**误判为"共享顶点"（`SHARED_VERTEX`），跳过这些圆心的定位尺寸。草图因此欠约束，求解器在 `SectionRegenerate` 阶段把被跳过约束的圆弧圆心任意平移，实测最大漂移 **12.350956902744 mm**。随后 MCP 的正确性检查发现几何偏离输入超过容差，直接拒绝该操作并回滚整个计划。

结果是：对含有同心圆弧的草图，`coordinates` 模式**完全不可用**；而 `autodim` 模式虽然能生成实体，但会引入约 **1.16 mm** 的曲率/圆心偏差（见第 4 节），同样无法得到几何精确的零件。

## 2. 复现步骤

最小复现草图（`SK P01-01`，XY 平面，单位 mm）：4 组同心圆弧，圆心分别位于 `(-22,0)`、`(22,0)`、`(0,62.759299)`、`(0,-62.759299)`：

### 3.2 源码证据

`native/sketch_coordinates.cpp` 第 184–195 行：`placed` 列表按 `|Δx|<1e-9 且 |Δy|<1e-9` 判断"已放置过该点"，命中即跳过该点的坐标尺寸：

```cpp
for (auto point : row["points"]) {
    double px = point["xy"][0].get<double>(), py = point["xy"][1].get<double>();
    bool shared = false;
    for (auto &v : placed)
        if (fabs(v[0] - px) < 1e-9 && fabs(v[1] - py) < 1e-9)
            shared = true;
    if (shared) {
        log("COORDINATE_SHARED_VERTEX_SKIPPED=%s_%s\n", prefix.c_str(),
            point["key"].get<std::string>().c_str());
        continue;                       // <-- 圆心定位尺寸被丢弃
    }
    placed.push_back({px, py});
    ...
}
```

这里的 `point` 同时包含 `center`、`start`、`end`。对同心圆弧，`center` 与已放置圆弧的 `center` 完全相同，于是被当作"共享顶点"跳过。但 Creo 草图里两条圆弧只是**圆心重合**，并不是圆心处有约束关系；跳过其中一条的圆心定位尺寸后，该圆弧在 X 方向自由，求解器可任意移动，最终产生 12.35 mm 漂移。

### 3.3 已尝试的规避（均失败）

1. 给内圈大圆弧圆心加 `1e-7 mm` X 偏移 —— 仍失败（默认容差下仍被判共享，且日志显示跳过的是 `ar03/ar04` 而非 `ar06/ar08`）。
2. 给全部 8 个圆弧圆心各加互异的 `1e-6 mm` X 偏移（远大于 `1e-9` 去重容差、远小于 TXT 源精度），并用新圆心反算所有端点，闭环误差 `2.0e-14 mm` —— 依然失败，仍是 `12.350957 mm`。

说明该缺陷不只来自"完全同心"，`coordinates` 模式对这种多圆弧闭环草图的尺寸布局本身就不稳定，用户侧无法通过微调输入规避。

## 4. 关联问题：autodim 也无法保持输入几何

改用 `dimensioning="autodim"` 后作业可成功（见 `job_id=9a804ca64c8e4138a054bd2672eadb35`，模型 `p01_part1_v2`，已保存重载验证，`20 面 / 48 边`，与 TXT 实测指纹 `20/49` 基本一致），但原生几何偏差检查报告：

```json
"geometry_deviation": {
  "enforced": false,
  "exceeds_warning": true,
  "max_deviation_mm": 1.1618304003038062,
  "measurement_scope": "named_section_entities",
  "tolerance_source": "default_autodim",
  "warning_threshold_mm": 0.001,
  "sample": [
    {"entity":"ar01","measurement":"center_radius_angles","deviation_mm":0.91905},
    {"entity":"ar03","measurement":"center_radius_angles","deviation_mm":0.97360},
    {"entity":"ar08","measurement":"center_radius_angles","deviation_mm":1.16183}
  ]
}
```

即 autodim 为让草图"全约束"而自动添加的尺寸，把圆弧圆心/半径/角度移动了最多 **1.16 mm**。对 12.5–54 mm 半径的轮廓，这是 1%–9% 量级的形变，直接导致体积与目标不符（本例 `69620.41 mm³` vs TXT 目标 `73119.149 mm³`）。

值得注意的是：输入草图本身的闭合性完美（`max_endpoint_gap_mm = 2.0e-14`，`weldable = true`），偏差完全是求解器引入的。MCP 已能测量并报告该偏差（`exceeds_warning = true`），但 `enforced = false`，既不阻止也不提供"保持输入几何"的求解选项。

## 5. 期望改进

1. **修复 coordinates 去重逻辑**：仅当两个实体在共享点处确实存在拓扑连接时才跳过尺寸；圆弧的 `center` 不应与另一圆弧的 `center` 当作共享顶点。建议按实体分别记录已放置点，或以 `(entity_id, point_key)` 为键去重。
2. **提供"刚性/保形"求解模式**：新增类似 `dimensioning="exact"` 或通过 `geometry_tolerance_mm` 强制求解器保持输入坐标（当前已有 `geometry_tolerance_mm` 字段，但 `coordinates` 模式下实测未生效）。当求解后偏差超过阈值时应拒绝，而非放行。
3. **保留显式尺寸**：`SketchDimension` / `SketchConstraint` 已支持用户给定尺寸，但 `coordinates` 模式会自动生成尺寸并覆盖；建议允许用户显式给定圆心/半径尺寸后，跳过自动坐标尺寸，避免同一草图被重复约束。
4. **autodim 偏差可配置**：公开 autodim 的公差/权重参数，或提供"仅添加必要约束、不改变量值"的选项，使几何精确保留。

## 6. 影响范围

- 所有含同心圆弧、共享圆心、或圆弧闭环的草图：`coordinates` 不可用。
- 需要几何精确（L3 验收）的零件：`autodim` 引入的 1.16 mm 偏差不可接受。
- 本任务中 Part1（环形链板）因此无法达到 TXT 给定的体积与重心指纹。
