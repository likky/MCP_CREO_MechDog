# CREO v0.26.0 核心问题：装配无法应用旋转位姿，且不支持子装配嵌套

- 日期：2026-11-18
- 服务：MCP_CREO_MechDog v0.26.0
- 宿主：CREO（本机 Toolkit 通道，mm 模板）
- 触发场景：按 M113 装甲车履带 TXT 附录 D 的 94 行实例表重建三级装配（Assem1 / Assem3 / Assem2）
- 结论：**装配位姿的旋转分量完全不可用**（TXT 给出的六位小数方向向量 100% 被内核拒绝）；**子装配不能作为组件来源**，三级装配无法按原结构重建。

---

## 缺陷 1：`assemble_component` / `component_placement` 拒绝任何非机器精度正交的旋转矩阵

### 现象

`ProAsmcompAssemble` 与 `ProAsmcompPositionSet` 对「正交但只有 6 位小数」的旋转矩阵返回 `-2`（Toolkit `PRO_TK_BAD_INPUTS`）。MCP 层准入通过（`rotation_matrix` 正交残差 2.3e-7 < 1e-6），但内核拒绝执行，作业整体回滚。

报错原文：

```text
Toolkit call ProAsmcompAssemble((ProAssembly)board, (ProSolid)child, position, &comp)
failed with code -2 during execute_assemble_component
```

`component_placement` 分支同样失败：

```text
Toolkit call ProAsmcompPositionSet(nullptr, &comp, position)
failed with code -2 during execute_component_placement
```

### A/B 证据（同一源件 `p04_pin_v260`，同一新建装配）

| # | 位姿 | 作业 | 结果 |
|---|---|---|---|
| 1 | `rotation_matrix = I`，`translation = [0,0,0]` | `979ceef4dc4240f4a4192e4afdd38903` | **succeeded** |
| 2 | `rotation_matrix = I`，`translation = [-67.129, 77.472, 0]` | `3e45662e2fd444919fa575d61148210d` | **succeeded**，回执 `transform[3] = [-67.129, 77.472, 0, 1]` |
| 3 | 绕 Z 旋转 2.74°（六位小数），同 #2 平移 | `7b41b88cb39a466baa6045e56d05293d` | **failed**，`ProAsmcompAssemble=-2` |
| 4 | 精确 90°：`[[0,-1,0],[1,0,0],[0,0,1]]` | `fcaafda0fbfa493aba8b795e77d4ef43` | **succeeded**，回执矩阵与输入逐位一致 |
| 5 | 先 identity 插入，再 `component_placement` 用 #3 的矩阵 | `4c090a6aae6544eeb6a708dfbab0a8cb` | identity 插入成功，**placement failed**，`ProAsmcompPositionSet=-2` |

#2 与 #4 成功、#3 失败，说明失败条件不是「非单位矩阵」，而是**矩阵的浮点正交性精度**：#4 是整数精确矩阵（det 精确为 1），#3 是按 `cos/sin` 六位小数拼出的矩阵（`det = 1.00000023`）。

### 矛盾点

1. `assemble_component` 的 `rotation_tolerance`（默认 1e-6）只放宽了 **MCP 侧准入**，内核不认这个容差；准入通过之后仍然必然失败，等于给了个无效开关。
2. `rotation_matrix` 文档明确写 "applied exactly as given: never transposed, orthonormalized or repaired"。这条设计选择直接导致：**凡是由外部数据（图纸、位姿表、其它 CAD 导出）给出的有限精度方向向量，都无法装配**。
3. `RELEASE_NOTES_0.19.1`（DEV-077/R01）称「4 位小数方向向量可在声明容差后装配」。实测 6 位小数仍然失败，该结论不成立（至少在本机 CREO 版本上）。

### 影响

TXT 附录 D 的 94 个实例中，**只有少数纯平移位姿可装配**（如 Assem1 的 Part2-1、Part4-2）。其余全部带旋转，逐实例装配 100% 失败。三级装配在 v0.26.0 上无法按给定数据重建。

### 规避（客户端侧，已在本次任务中验证）

在提交前对旋转矩阵做 Gram-Schmidt 正交化（保持第一行方向，第三行取叉积并校正右手性），把数值压到机器精度。本任务 275 个位姿正交化后最大分量改动 `5.99e-07`，对 2.75 m 跨度是亚微米级，远小于 TXT 的 0.001 mm 量级：

```
2026-11-18: 正交化后 Assem1 4/4 装配成功（job 308474bc1373452f8da2488733e8d938）
2026-11-18: 正交化后 Assem3 2/2、Assem2 269/269 全部成功（job fd20d712... / 583735294... + f30fbbdb...）
```

正交化后一共 275 个位姿（4 + 2 + 269）全部被内核接受，反向印证失败条件确实是矩阵精度而非旋转本身。

### 建议

- 增加一个显式开关（例如 `rotation_repair: "orthonormalize"`），在**调用方明确同意**的前提下把矩阵投影到最近的 SO(3) 上，并回执修正量；
- 或者在内核返回 `-2` 时识别该情形并给出可诊断的错误（当前报错只有 `code -2`，无法判断是「轴不在平面内」「矩阵不正交」还是「源件不健康」）；
- 文档应改为：`rotation_tolerance` 只影响 MCP 准入，内核要求机器精度正交。

## 缺陷 2：子装配不能作为组件来源，三级装配无法表达

### 现象

对新建装配插入 `assem1_link_assembly`（`model_id = 95a7ff3e2aa44508b4bb099b81d30953`，本身由 `creo_new_assembly` 创建）：

```text
Nested assembly copying is not yet supported; insert owned part/sheetmetal models
```

错误在计划准入阶段返回，**不创建作业**（无 job_id）。源码路径 `native/advanced.cpp` 的 `assemble_component()` 里显式判断：

```cpp
if (child_type == PRO_MDL_ASSEMBLY)
    throw std::runtime_error(
        "Nested assembly copying is not yet supported; insert owned part/sheetmetal models");
```

`docs/COVERAGE_0.21.md` 也写明「子装配在提交前被拒绝」，与实现一致。

### 影响

TXT 明确要求三级装配（P07 Assem1 = 4 组件、P08 Assem3 = 2 组件、P09 Assem2 = 94 组件，其中 44 个 Assem1 + 43 个 Assem3）。在 v0.26.0 上只能：

- 建出 Assem1、Assem3 两个子装配（各自 4 / 2 个实例，质量属性可核）；
- Assem2 退化为**展平的零件级装配**：44×4 + 43×2 + P05×1 + P06×5 + Part1×1 = **269 个零件实例**。

几何等价（位姿按 `M_part_in_sub @ M_sub_in_asm2` 合成，实测与 TXT 的 A 读法残差 0.0148 mm），但**装配结构不等价**：BOM 层级、组件计数（94 vs 269）、装配态干涉检查与后续替换都会不同。

### 建议

- 支持「插入受管子装配」的最小路径：允许 `assemble_component` 接受 `model_type = assembly` 的受管模型，按快照复制；
- 若短期不做，至少在 `creo_new_assembly`/`assemble_component` 的能力说明里给出「展平重建」的推荐做法与位姿合成约定，避免调用方按三级结构设计后才发现无法落地。

## 缺陷 3（次要）：`creo_new_assembly` 回执的 revision 与真实值不一致

### 现象

```text
creo_new_assembly(model_name="assem1_link_assembly")
→ { "model_id": "95a7ff3e2aa44508b4bb099b81d30953", "revision": 0, "status": "queued" }
```

等待作业 `succeeded verified` 后，用回执里的 `expected_revision = 0` 提交首个 `execute_plan`：

```text
Stale revision: model_id=95a7ff3e2aa44508b4bb099b81d30953 current_revision=1 expected_revision=0;
no job was created
```

改用 `expected_revision = 1` 才被接受。`models/<id>/model.json` 也确认 `revision: 1`。

### 影响

回执返回的是**创建前的占位修订号**，而调用方按 `docs/ASSEMBLY_REBUILD.md` 的流水线（"capture the ACTUAL value; do not assume 0"）会先等作业完成再读回执——此时回执的 0 已经过期。每个新建装配都要多一次 `creo_inspect_model` 或一次被拒的写入才能继续。

### 建议

- `creo_new_assembly` 在作业终态后再回填真实 revision；或
- 回执里明确区分 `revision_before` / `revision_after`，并把当前生效值放在同一字段。

## 附：本次任务因此产生的交付差异

1. **位姿**：TXT 附录 D 的六位小数方向向量在提交前被正交化，最大分量改动 `5.99e-07`。位姿自校验（用 TXT 自己的零件质量属性回代）结果：Assem1 残差 0.0002 mm、Assem3 0.0001 mm、Assem2 0.0148 mm（TXT 记录 A 读法残差 0.015 mm）——说明正交化没有改变位姿语义。
2. **结构**：Assem2 由 94 个实例展平为 269 个零件实例，BOM 层级与 TXT 的 P09 不同（几何与质量属性等价）。
3. **规模**：单作业 200 操作上限使 269 个实例必须拆成两个作业（135 + 134），第二个作业依赖第一个作业的 `expected_revision`，中途失败无法整体回滚。

## 附：验收回读证据（`creo_list_components` 与提交计划逐位比对）

装配完成后立即用 `creo_list_components` 回读组件表，把每个组件的 `transform`（`component_to_assembly`，4×4 行向量，末行 = 平移）与提交计划里的 `rotation_matrix` / `translation` 做逐位差分：

| 装配 | model_id | rev | 组件数 | 计划数 | `dR` 最大 | `dT` 最大 | `|det−1|` | 约束 | 源件匹配 |
|---|---|---|---|---|---|---|---|---|---|
| Assem1 `assem1_link_assembly` | `95a7ff3e2aa44508b4bb099b81d30953` | 2 | 4 | 4 | 2.035e-13 | 0.0 | <1e-9 | 4×`fix` | 4/4 |
| Assem3 `assem3_link_pair` | `7b95dc211eb642099d18d366a2220b58` | 2 | 2 | 2 | 1.225e-16 | 0.0 | <1e-9 | 2×`fix` | 2/2 |
| Assem2 `assem2_track_assembly` | `db36f5197d3548bfadef5f0275a2fa17` | 3 | 269 | 269 | 5.032e-13 | 0.0 | <1e-9 | 269×`fix` | 269/269 |

结论：

- **MCP 未对位姿做任何隐式改写**——回读矩阵与提交的 Gram-Schmidt 正交矩阵差异在 1e-13 量级（仅为双精度十进制序列化的舍入），平移分量为逐位相同（`dT = 0.0`）。
- **275 个组件全部实例化成功且无遗漏/多余**（`label` 集合与计划集合完全相等）。
- `|det − 1| < 1e-9`、约束类型全部为 `fix`，说明组件以「固定」方式落位，不会因装配约束求解而漂移。

复现脚本：`verify_pose_readback.py`（同目录，只做 JSON 解析 + 浮点差比较，不接触 CAD 内核）。

> 注：`creo_list_components` 对 269 组件装配的返回体约 **10.97 MB**（10,968,626 字符），超出单次工具返回上限，被宿主落盘。建议 MCP 侧对大型装配提供 `fields`（如只回 `label/transform/source_model_id`）或分页参数，否则调用方只能绕道读落盘文件。
