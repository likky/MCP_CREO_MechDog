# 2026-11-17 CREO MCP v0.26.0 反馈：旋转轴与截面不共面的静默失败 + weld 校验顺序自相矛盾

- 反馈对象：MCP_CREO_MechDog v0.26.0
- 建模场景：仅依据一份自然语言 TXT，用 `creo_execute_plan` 重建 M113 履带零件（P05 轮毂，Ø480×252，轮心 (92.075, −270.076)，轴线平行 Z）
- 操作系统 / CREO：Windows，CREO 会话正常，同一会话内其余 5 个零件均已完成
- 结论：本轮遇到 3 个问题，其中 2 个会直接阻断"可参数化重建"，1 个会让错误操作被当成成功

---

## 问题 1（阻断级）：基准轴与草图平面相差 0.39 µm 时，revolve 两种模式都失败，且报错完全不指向真实原因

### 复现

轮心轴由两个偏置基准面求交得到（v0.26.0 没有"过点轴"）：

```json
{"op":"datum_plane","label":"p05_px","reference":{"kind":"datum_plane","axis":"x"},"offset":92.07461}
{"op":"datum_plane","label":"p05_py","reference":{"kind":"datum_plane","axis":"y"},"offset":-270.076285}
{"op":"datum_axis","label":"p05_axis_z","references":[
  {"kind":"datum_feature","label":"p05_px"},
  {"kind":"datum_feature","label":"p05_py"}]}
```

环形内腔草图放在 **YZ 平面 offset = 92.075**（TXT 附录写的是 `0.092075 m`，即 92.075 mm；而轮心 X 的实测值是 `0.09207461 m` = 92.07461 mm）。

于是轴在 x = 92.07461，截面在 x = 92.075，**两者差 0.39 µm（3.9e-4 mm）**。

### 现象

| 作业 | 模式 | 结果 |
|---|---|---|
| `de60d9299a5f48128d57213595d68988` | `mode:"cut"` | `failed` / `execute_revolve`：`Revolve cut removes no material`，`volume before = after = 43621642.313624978065`，`CUT_MATERIAL_REMOVED_MM3=0.000000000000` |
| `f338af7f1c374c2185ec832c42182034` | `mode:"add"` | `failed` / `execute_revolve`：`Regeneration produced a failed, suppressed or incomplete feature` |
| `992fc568eb7c4c6494219ddac8aefbbc` | `mode:"cut"`（仅把基准面改成 92.075） | `succeeded`，11/11 操作通过，体积 18 463 562 mm³ |

三份作业的草图实体、旋转角（360°）、轴标签完全相同，唯一差异是**轴与截面平面的共面性**。

### 证据（native.log，作业 de60d9…）

```
ProFeatureWithoptionsCreate=0
created_feature_id=232
ProSolidRegenerate((ProSolid)board, PRO_REGEN_NO_FLAGS)=0
volume_mm3=43621642.313624978065
CUT_MATERIAL_REMOVED_MM3=0.000000000000
BUILD_FAILED=Revolve cut removes no material; check the sketch position, direction and depth
  against existing geometry Sketch origin (mm) = (92.075, 0, 0); normal = (1, 0, 0);
  direction sign = 1. Effective depth interval is unavailable (revolve_cut_has_no_linear_depth).
```

特征创建返回 0（成功），没有 ProErrorList，也没有任何"轴不在截面平面内"的提示。

### 影响

- 报错把排查方向完全带偏：`sketch position / direction / depth` 三项都正确，`revolve_cut_has_no_linear_depth` 更像在解释"深度不可用"，读者不会想到去查 0.39 µm 的共面误差。
- 这种亚微米量级的偏差在"从文本数值重建"里是常态：同一份 TXT 的 X 位置在不同章节分别写作 92.075 与 92.07461（0.092075 m / 0.09207461 m），任何按章节取数的人都会撞上。
- `mode:"add"` 时报错又换了一种说法（`Regeneration produced a failed…`），两种模式给出的诊断彼此不相关，无法互相印证。

### 建议

1. revolve 前显式校验 `|(axis_origin − sketch_origin) · sketch_normal| <= tol`，超差时报
   `revolve_axis_off_section_plane`，并给出实测偏心量与两个可选修正（把轴投影到截面平面 / 把截面移到轴所在平面）。
2. 或按 CREO 的常规行为自动把轴投影到截面平面（偏移量 < 1e-3 mm 时），并在回执里记录 `axis_projected_mm`。
3. `revolve_cut_has_no_linear_depth` 不应出现在"因轴退化而零切除"的诊断里，它只适用于 extrude。

## 问题 2（阻断级）：计划校验器在提交前拒绝 0.2–1 nm 级接缝，而它推荐的 `endpoint_policy=weld` 只在提交阶段生效

### 复现

同一份计划在 `creo_execute_plan` 的**入参校验阶段**就被拒绝（没有生成作业）：

**（a）operations[19] = SK P05-08（10 个长圆孔，20 段弧 + 20 条直线）**

```
operations[19]: Solid extrude profile rejected: detected 10 closed contour(s),
0 open contour(s) and 40 curve entities; [near_tolerance] endpoints joined only by
the closure tolerance (ar03/ln26) near (-35.1944202, -77.8924787) mm.
Supply disjoint or nested closed loops; the native solver remains authoritative for
anything this check cannot confirm.
Remediation: set closure_tolerance_mm, merge the arcs into one polyline, or use
snap_endpoints / endpoint_policy=weld; weld is applied at submission time, not during
plan validation.
```

**（b）operations[25] = SK P05-11（3 个 R50+R5 透镜缺口）**

按上一条 remediation，给该草图显式加了：

```json
"endpoint_policy": "weld",
"max_endpoint_move_mm": 0.002
```

仍然被同样理由拒绝：

```
operations[25]: Solid extrude profile rejected: detected 3 closed contour(s),
0 open contour(s) and 6 curve entities; [near_tolerance] endpoints joined only by
the closure tolerance (ar01/ar04) near (137.416018, -291.151311) mm.
```

### 根因

- 两个草图的接缝间隙来自 TXT 的 6 位小数：圆弧端点由"圆心 + 半径 + 角度"算出，直线端点单独给出，两者相差 **1.1e-6 mm** 量级（`ar01/ar04` 实测 1.104e-06 mm）。
- 校验器把"≤ 闭合容差但不是精确相等"的接缝判为 near_tolerance 并拒绝；而 `endpoint_policy=weld` 是**提交时才执行**的，所以它永远不可能让校验通过——remendiation 文本自己写了这一点，等于给了一个必然无效的修法。
- 对纯弧线闭合环（P05-11 的 3 个透镜全是弧），用户也没有"snap"手段：移动弧端点会改变半径，`snap_endpoints` 只吸附直线端点。

### 影响

- 只能把弧线降级成折线才能提交：P05-11 的 6 段弧被转成 3 条 50 点闭合 polyline（3° 步长，R5 弦高 < 0.002 mm），P05-05/P05-08 也只能先做直线吸附。对手工精确复现 CAD 曲线而言，这是实质性的精度损失。
- 计划校验发生在 weld 之前，这一点在报错里写明了，却仍被列为 remediation，增加一轮试错。

### 建议

1. 校验器接受 `endpoint_policy=weld` + `max_endpoint_move_mm` 作为放行条件：只要所有接缝间隙 ≤ max_endpoint_move_mm，就放行并在提交时焊接（这正是 weld 的语义）。
2. 或在 `sketch` 上提供 `closure_tolerance_mm` 的**显式**说明：它是"判为不闭合"的阈值，调大只会更容易被判 near_tolerance，不能用来放行。
3. 给纯弧环提供 `weld_arcs`：允许在 1e-6 mm 量级内平移弧端点并把半径修正记录到回执，而不是只支持直线吸附。

## 问题 3（正确性）：切除特征把体积"切"大了，却仍以 `CUT_MATERIAL_REMOVED_MM3=-3.06` 记录

### 复现

作业 `dd39ab8ceb3d4f0e87eb384fafc784a4` 的第 26 个操作 `p05_notch_cut`（`extrude`，`mode:"cut"`，`direction:"negative"`，`through_all`）：

```
volume_mm3=12514487.330518638715
volume_mm3=12514490.389585861936
CUT_MATERIAL_REMOVED_MM3=-3.059067223221
```

`execution_status=failed`（`Extrude cut removes no material`），但回执里"切除量"是**负数**——即该操作让实体变大了 3.06 mm³。

### 影响

- 负数切除量在语义上不可能出现；把它写进回执会让人怀疑体积读数本身。
- 既然 `removed` 可以是负数，"`removed == 0` 才算没切到"这条判据就不成立，`no_effect` 的判定应改为 `removed <= epsilon` 并单独报告 `added`。

### 建议

1. `volume.after > volume.before` 时回执记 `added_mm3` 并明确 `status="material_added"`，不要用负的 `removed`。
2. 该分支下仍应 `failed`（现状正确），但要提示"刀路方向可能反了"，因为方向反了正是最常见的成因（本例把 −Z 改成 +Z 后才切到轮毂凸台）。

## 附：本轮可复用的绕过方式（供其他使用者参考）

1. **轴与截面共面**：基准面偏置必须与草图 offset 用**同一个数值**（本例都用 92.075），不要一处用 92.075、一处用 92.07461。
2. **弧-线接缝**：提交前把直线端点吸附到"圆心+半径+角度"算出的精确端点（容差 1e-3 mm），可让 10 个长圆孔通过校验。
3. **纯弧环**：只能转成单条 `closed:true` 的 polyline；R5 弧用 3° 步长时弦高 0.0017 mm，仍在 TXT 的 L2 近似允许范围内。
