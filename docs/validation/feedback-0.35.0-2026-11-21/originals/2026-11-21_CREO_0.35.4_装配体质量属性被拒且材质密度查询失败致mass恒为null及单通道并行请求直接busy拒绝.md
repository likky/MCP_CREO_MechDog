# CREO MCP 反馈：装配体质量属性被拒 + 材质密度查询失败致 mass 恒为 null + 单通道并行请求直接 busy 拒绝

- 反馈日期：2026-11-21
- 运行版本：**0.35.2**（本机实测复现；`creo_startup_status` 报 `current_version: 0.35.2`、最新版 **`0.35.4`**、`update_available`）
- 本机未装 0.35.4，以下现象均在 0.35.2 上复现；文件名按用户要求用**最新版本号 0.35.4** 命名。
- Creo：Creo 9.0.0.0（`release_numeric = 41`）
- 宿主：Windows 10 19045，MCP 以 stdio 方式接入
- **正面说明（重要）**：上一轮 0.33.0 反馈的"启动协调器拒单"缺陷，在 0.35.2 上**已修复**——本次 `creo_startup_status` 一次即 `state: ready / connected: true / verification_age_seconds: 19`，7 个零件 + 17 实例总装全部建模成功并保存重载验证通过。本文只记录本轮新发现的能力边界/可改进点。

---

## 一、背景

本次任务：仅用 MCP 从一份 TXT 建模六足行走机构（7 零件 + 17 实例总装），几何数据 100% 来自 TXT。建模全部成功后，在**验收环节**（用质量属性核对 TXT 给出的体积/重心基准）遇到以下 3 个能力问题。

---

## 二、问题 1：装配体质量属性被拒（影响总装验收）

对总装 model 调用 `creo_get_mass_properties`：

```
creo_get_mass_properties(model_id=<assembly>)  ->
  Error: "Mass properties for assemblies are unsupported; query managed parts individually.
          use_tool: creo_inspect_model (read-only component and model inspection)"
```

- 工具说明里确实写了"assemblies are refused until their own query path is verified"，所以这是**已知且有意的设计**，不是 bug。
- 但**实际影响**：TXT 给出的验收基准包含总装级 ΔV / ΔA / ΔCG（`装配 17 实例总装｜143488.3150｜78622.3179｜(33.98798, -6.79044, -0.64157)`）。用户要在 Creo 侧复核总装体积/重心时，无工具可用；`creo_inspect_model` 只读组件与模型信息，不提供整体质量属性。
- **建议**：
  1. 增加 `creo_get_assembly_mass_properties`（遍历组件体积 + 各自变换累加重心），哪怕先给"体积求和 + 加权重心"的近似值；
  2. 或在 `creo_inspect_model` 的 assembly 结果里附一个 `aggregate_volume_mm3` / `aggregate_center_mm` 汇总字段。

---

## 三、问题 2：材质密度查询失败，导致 mass 恒为 null（7/7 零件复现）

对每个零件的 `creo_get_mass_properties` 返回：

```json
{
  "volume_mm3": 68734.57,
  "center_of_mass_mm": [33.375, -15.296, -7.724],
  "mass_g": null,
  "mass_source": "none",
  "density_g_cm3": null,
  "density_source": "none",
  "mass_unavailable_reason": "material_query_failed",
  "material_assigned": true,
  "material_unit": "tonne",
  "native_mass_unit": "tonne",
  "hint": "The model material could not be measured; mass is unavailable",
  "query_codes": {"volume": 0, "mass": -1, "units": 0}
}
```

- **7 个零件全部** `mass_unavailable_reason: "material_query_failed"`，尽管 `material_assigned: true`。
- 工具说明称"无材质时可传 density_g_cm3 做 what-if"，这确实可用——但**即使模型已分配材质，也查不到密度**，只能靠调用方显式传密度。对"材料已指定就要能读出质量"的直觉预期是落空的。
- 可绕过：传 `density_g_cm3` 即可得到 mass（本次未用到，因为 TXT 验收基准是体积/重心，不需要质量）。
- **建议**：
  1. 排查 `ProMaterial...` 密度读取路径为何在 `material_assigned:true` 时仍 `material_query_failed`，并在错误信息里给出具体失败的 Toolkit 调用名（现在只有抽象原因码）；
  2. 若 SDK 本就不能从该材质取密度，在 `hint` 里明确写"该材质无密度字段，请传 density_g_cm3"，避免用户以为是临时故障。

## 四、问题 3：单通道并行请求直接 busy 拒绝、无排队（符合契约但需提示）

在一次并行发起 3 个 `creo_get_mass_properties`（不同 model_id）时，2 个被直接拒绝：

```json
{
  "status": "busy", "code": "toolkit_busy", "accepted": false,
  "blocking_job_id": null, "blocking_model_id": null, "blocking_operation": null,
  "owner_snapshot": null, "owner_determined": false,
  "retry_after_seconds": 5,
  "retry_guidance": "No occupying job could be determined; ... A suggested retry interval is 5 seconds, not a completion estimate ...",
  "message": "Creo Toolkit is busy with another operation"
}
```

- `capabilities.scheduling` 明确写了 `admission: reject_busy_without_creating_a_job`、`queue_guarantees: "No public FIFO, capacity or admission-wait guarantee"`，所以这是**符合已声明契约**的行为。
- 但从调用方（尤其是 LLM 客户端）角度，同时查多个零件质量属性是很自然的批量操作，直接返回 busy 且 `owner_determined:false`（连是谁占用都不知道），只能自己串行 + 重试。
- **建议**：增加一个"批量只读查询"工具（如 `creo_get_mass_properties_batch(model_ids[])`），在服务内部串行执行，避免把单通道细节暴露给调用方。

---

## 五、问题 4（提示类）：失败作业的几何描述需要调用方人工核对

建模过程中有 2 次失败，错误信息质量**很好**，值得肯定：
- P02：`"Extrude cut removes no material ... Sketch origin (mm) = (5, 0, 0); normal = (1, 0, 0); direction sign = 1. Effective depth 0.6 mm spans [0, 0.6] mm along the reported axis."` —— 直接点出草图原点、法向、方向、深度区间，据此立刻定位到"锥形凹切在了盘外"。
- P05：`"Sketch origin (mm) = (0, 0, 0); normal = (1, 0, 0); ... through_all_has_no_finite_depth"` + `cut_geometry_context` 结构化回执。

这不是缺陷，但反映一个事实：计划里草图平面的 u/v 轴含义（YZ 平面 u=y、v=z）若被误读，孔会落到轮廓外，MCP 无法替调用方判断"这个孔本该在哪"——这是几何语义问题，非 MCP 责任。仅记录以供其他使用者参考。

## 六、本轮结论

| 维度 | 结果 |
|---|---|
| 启动/就绪（0.33.0 的老问题）| **已修复**：一次即 ready，全程稳定 |

按优先级：**P1** 装配体质量属性汇总；**P2** 材质密度查询失败的具体原因与文案；**P2** 批量只读查询工具。
