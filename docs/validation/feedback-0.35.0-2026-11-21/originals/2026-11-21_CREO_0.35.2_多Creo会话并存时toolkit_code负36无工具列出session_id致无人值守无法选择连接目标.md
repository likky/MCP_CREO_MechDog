# 2026-11-21 CREO 0.35.2 — 多 Creo 会话并存时 toolkit_code=-36，无工具可列出 session_id，无人值守客户端无法选择连接目标

> 版本说明：本机实跑并复现的是 **0.35.2**（MCP 自报最新版 0.35.4，本机未安装、未在 0.35.4 上验证）。
> 本问题在给总装着色前触发：着色工具 `creo_recolor_assembly` 本身可用，但所有连接类工具被会话歧义挡住，无法提交作业。

---

## 1. 核心问题

同一台机器上运行着**两组 Creo 会话**（各含 parametric.exe + xtop.exe）时，MCP 的 Toolkit 连接探测返回 `toolkit_code = -36`（`PRO_TK_E_AMBIGUOUS`），启动协调器进入 `state: selection_required`，**所有需要真实连接的工具（建模、着色、检查等）一律拒单**。

要解除歧义只有两条路：
1. 人工关闭多余会话，只留一个，再 `creo_startup_status(retry=true)`；
2. 在 config.json 里设置 `creo_session_id` 后**重启 MCP 服务**（仅改文件对运行中的服务无效）。

但**当前没有任何工具能列出可选会话的 session id**，因此一个无人值守的客户端（AI agent）无法程序化地知道自己该选哪个会话——只能靠人肉猜 PID 再去关进程。对自动化流程这是硬阻断。

MCP 自己在返回的 `terminal_reason` 里也承认了这一点：

> "No tool can list session ids yet, so an unattended client cannot choose a session programmatically"

---

## 2. 复现步骤

1. 机器上启动两组 Creo（本次：旧组 11-20 18:04 起 PID 26376/25840，新组 11-21 19:29 起 PID 11196/9932）。
2. `creo_startup_status({})` → `state: selection_required`、`connected:false`。
3. `creo_session_status({})` → `connection_state: ambiguous`、`toolkit_code:-36`、`worker_exit_code:20`。
4. 关闭新组进程（仅留旧组），`creo_startup_status({retry:true})` → 约 40 秒后 `state:ready`、`connected:true`、`toolkit_code:0`，连接恢复。

## 4. 影响

- 任何依赖真实 Toolkit 连接的操作（建模、着色、打开/保存/检查模型）在多会话场景下全部拒单。
- 会话歧义可能**自发出现**：本次建模完成后，机器上不知何故多起了一组 Creo（19:29，晚于建模完成的 19:20），并非用户有意开第二组——说明 Creo 会话生命周期与 MCP 服务不同步是常态风险，而非罕见边缘情况。
- AI agent 无法自行选择会话，任务被迫中断等待人工介入。

---

## 5. 修复建议

**P0（解自动化硬阻断）**
1. 新增只读工具 `creo_list_sessions`，返回当前可见的 Creo 会话列表及其 `session_id`、`pid`、启动时间、窗口状态、当前承载的模型名——让客户端能程序化地识别目标会话。
2. 在 `creo_startup_status` 的 `selection_required` 返回体里直接附上该列表，省去一次额外调用。

**P1（降低歧义发生）**
3. 协调器在启动/连接时若发现多会话，优先选取承载 MCP-managed 模型、或 session identity 与最近一次 verified save 匹配的那一组（`session_health` 已有 identity 记录），自动消歧而非直接拒单；无法判定时再报 `selection_required`。
4. 允许通过工具参数（而非仅 config.json + 重启服务）临时指定 `creo_session_id`，例如 `creo_startup_status(retry:true, session_id:"...")`。

**P2（可观测性）**
5. `creo_session_status` 的 `creo_process_snapshot` 已有 pid/启动时间，但缺每个进程对应的 session id——补上该字段即可让客户端从进程快照直接选会话。
6. `session_health` 的 "changed/sessions_observed" 应给出具体增删了哪个会话，便于诊断歧义来源。
