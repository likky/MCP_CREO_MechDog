# 0.25.0 发布记录勘误（2026-11-16）

本文件只补记 0.25.0 已发布文档中的基线与证据口径，不改写、不重传已发布的 tag、四附件和
`docs/validation/RELEASE-0.25.0.md` 原件。原件与附件保持逐字节不变；差异以本勘误与统一
[发布后核对入口](RELEASE-POSTCHECK-2026-11-07.md) 的 `## v0.25.0` 段为准。

## 1. 上一正式包标注

`RELEASE-0.25.0.md` 的以下三处把直接前版写成 0.24.0：

- `## 包内容对照（相对 0.24.0）`
- `## 相对上一正式包核对（上一版本：0.24.0）`
- worker 对照行的「0.24.0 构建」

按 0.25.0 反馈报告引用的 GitHub Release 列表（`v0.25.0, v0.24.1, v0.24.0, ...`），0.25.0
的直接前版是 **0.24.1**；同文件第 27 行也已写「本版从已发布的 0.24.1（`e1ee731`）合入」。
因此「包内容对照」实际跨过了 0.24.1，不包含该版的启动参数、无图形容错、worker 回退与
`toolkit_hint` 变更。

2026-11-16 已用 GitHub Releases API 复核（`releases?per_page=5`）：列表中 v0.25.0 之后
紧邻 v0.24.1，四个附件名/字节/digest 与 POSTCHECK 一致；`git/ref/tags/v0.25.0` 指向标签对象
`f617e5d…`，本地标签再指向 `38bee48…`。因此直接前版为 0.24.1 已获远端独立证据。升级者应以
0.24.1 为直接基线；若要判断 0.25.0 相对 0.24.0 的跨版差异，应显式标注「跨 0.24.1」。已发布正文与包内快照不回写，后续版本在
`docs/releases/<version>.json` 中冻结 `previous_version` / `previous_release_tag` /
`previous_release_commit`，并由门禁比对 `上一版本：` 标签。

## 2. 0.24.0 单测统计口径

0.25.0 反馈仍指出 `RELEASE-0.24.0.md` 的「单测 3494 → 3548 全量通过」掩盖了同一环境的
3567 通过 / 3 失败。该行属于 0.24.0 的历史快照，本次不回改；0.25.0 的
`Ran 3655 tests OK` 是作者本机 `dev_check.py` 的结果，反馈方未复现，也不与本机
Creo 10 环境或反馈方子集结果拼成同一场测试。引用单测数字时必须同时写明来源环境与
源码提交；不同源码、不同宿主的结果不能合并成「全量通过」。

## 3. 发布后核对措辞（P3-5）

`RELEASE-0.25.0.md` 在 tag 处已写 `--tag v0.25.0 → exit 0`，而该快照产生时远端核对尚未
执行。实测结果与事实一致，但包内快照无法区分「预期」与「已核验」。自 0.26.0 起：

- 冻结包的发布记录必须写「发布后执行，当前未验证」；
- `remote_verification: pending` 期间，包内记录不得出现 `--tag … exit 0`、
  「four assets downloaded and verified」等远端已验措辞；
- 真实远端结果只追加到 `main` 的 POSTCHECK 段，不回写冻结包。

## 4. TXT 证据分发

0.25.0 及更早版本的 `docs` 打包白名单只收 `.md/.json`，两个 TXT 特例硬编码在
`tools/package.py`。0.26.0 起以 `docs/distribution_evidence.json` 审定清单逐文件记录
`bytes`/`sha256`，打包时校验字节一致；未列入的 TXT（含配置、日志、用户模型、SDK/许可
数据）仍然不入包。旧版本已发布包不重新打包。

## 未验证

- 未重跑 0.25.0 / 0.24.x 的单元测试或原生验收；远端信息只核对了 Release 列表顺序、标签对象和附件摘要；
- 未改写、未重传任何已发布标签与附件。
