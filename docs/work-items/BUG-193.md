# BUG-193：`surface_loft` / `creo_loft` 运行时就绪披露失真且未在提交前拦截未就绪 callback

类型：缺陷。优先级：P1/P2。

分类：**已有修复但待验收**。0.46.0 交付 `loft`/`surface_loft` 统一 `runtime_ready` 披露与 before-job callback 预检拦截。关联：[BUG-135](BUG-135.md)、BUG-120、FEAT-074。 [发布记录](../validation/RELEASE-0.46.0.md)

## 来源与现象

2026-11-26 外部 0.45.1 / Creo 10.0.0.0 反馈 §3 与 §4（[原件](../validation/feedback-0.45.1-2026-11-26/originals/draft-flip-loft-arc-weld.md)）。

- Creo 10 上 `surface_loft` 的 `element_tree` 路线触发 `-18`，`resident_panel` 与 `creo_loft` 在未启动辅助应用 callback 时失败于 `BLEND_CALLBACK_SETUP_REQUIRED`。
- `creo_capabilities` compact 在首次失败前仅显示 `enabled=true`，`_panel_route_document` 计算 `runtime_ready` 时未检查 callback 状态。
- `creo_loft` 与 `creo_surface_loft(creation_route="resident_panel")` 在 callback 未加载时仍先抢占通道建立 job，进入原生 `callback_preflight` 才失败回滚。

## 范围与验收

1. `capabilities.py` / `capability_pages.py` 为 `loft` 与 `surface_loft`（含 `element_tree`、`resident_panel` 两条路线）统一输出 `runtime_ready` 与 `runtime_admission`，将 callback 就绪状态与已知 Creo 10 `release_numeric=42` 的 `element_tree` `-18` 限制纳入判定，并在 compact 页可见。
2. `generic_bridge.py` 在 `submit()` 抢占通道/建 job 之前对 `loft` 与 `surface_loft(creation_route="resident_panel")` 执行 callback 预检；未就绪时直接 before-job 拒绝并附带结构化 `callback_status` 与 `callback_free_route`，不占用通道、不产生失败 job。
3. 前置明确 `accept_unverified_completion` 在 Creo 10 上不能保留几何的说明；同步更新 `mcp_contract.py` 与离线/实机验证。
