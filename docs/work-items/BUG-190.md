# BUG-190 结构化失败诊断在 get_job 回执中不可发现

分类：**已有修复但待验收**。可用性，P2，目标版本 0.44.0。

来源为 [0.43.0 反馈](../validation/feedback-0.43.1-2026-11-24/originals/chamfer-propagate-and-surface-loft-creo10.md) N2。`round_failure`、`failed_loft_input`、`loft_checks`、`verify_stages` 只写在 `jobs/<job_id>/native_result.json` 的 `operations[]` 里；`creo_get_job` 回执没有路径或失败阶段，报错文案只说 `see round_failure.edge_diagnostics`，调用方第一遍会在顶层拿到 `null`。

## 范围

- `creo_get_job` 回执增加 `failed_operation_index`、`failed_stage`、`failure_phase` 与 `native_result_path`。
- `round_failure` 至少摘要 `failed_reference_index` 与两个顶点的 `min_adjacent_edge_mm`。
- 报错文案改为 `see operations[<i>].round_failure.edge_diagnostics in native_result.json`。

## 验收

用已有失败作业回读 compact 与 full 两种 detail，字段齐全且指向真实文件；成功作业不新增噪声字段；离线单测覆盖字段投影。

## 交付与证据（2026-11-24）

- 实现：`bridge.py` 的 `_read_job`/`compact_job` 在 `failed`/`unknown_outcome` 作业顶层透传 `failed_operation_index`、`failed_stage`、`failure_phase`、`native_result_path`（仅文件真实存在时）及 `round_failure_summary`（含 `failed_reference_index` 与 `edge_min_adjacent_mm`），成功作业零新增；`native/generic.cpp` 的 `round_failure` 报错改为 `see operations[<i>].round_failure.edge_diagnostics in native_result.json`。
- 验证：`tests/unit/test_dev101_phase2.py::Bug190JobFailureDiagnosticsTests` 覆盖 `full`/`compact` 与成功作业零噪声，原生构建通过。未验：WorkBuddy 黑盒。
