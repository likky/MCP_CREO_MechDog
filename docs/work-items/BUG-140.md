# BUG-140：启动构建指纹急切展开 legacy 候选导致准备阶段超时

分类：**部分交付 0.35.0，剩余待验收**

类型：缺陷

优先级：P1

状态：部分交付 0.35.0，剩余待验收（已发布；惰性求值与 8 依赖上限离线通过；真实构建缓存端到端计时未验）

目标版本：0.35.0

来源与关联：[0.33.0 反馈归档](../validation/feedback-0.33.0-2026-11-21/SOURCE_MANIFEST.json) `startup-chamfer.md` P1；关联 `bridge.py`、`src/creo_mechdog/build_fingerprints.py`、BUG-139。

## 问题或目标

0.32.0 报告称现代算法缓存已命中或不匹配时，调用方仍先计算 `legacy_digest_candidates()`，10 个依赖产生大量无用组合，准备耗时约 236 秒并超过启动预算。需在当前源码复现计时与调用路径，再改为仅在旧缓存确需兼容候选时计算，并限制异常规模；不得改变当前指纹算法、产物身份或缓存安全语义。

## 范围

包含惰性候选求值、旧缓存兼容路径、规模保护与定向性能/行为回归。不包含调整启动总预算或以跳过指纹校验换取速度；BUG-139 已交付的启动相位与探测预算不重复开发。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | 构建指纹与 bridge 定向单测 | 新算法缓存路径不调用 legacy 生成器；旧缓存仍能匹配合法候选；伪造或不匹配摘要不放行 |
| Windows / Python | 10+ 依赖的合成计时回归 | 新算法缓存路径不展开指数组合，耗时与调用次数有明确证据 |

无原生逻辑改动时不以编译或 Creo 实机代替上述回归。

## 实现与证据

2026-11-21 按当前 0.34.0 源码复现并修复（离线，未实机）：

- 复现：10 依赖快照调用 `legacy_digest_candidates` 产生 1024 个候选，耗时 0.415647 s；即使现代缓存已命中也会先展开。
- 修复：`match_cached_fingerprint` 接受惰性候选工厂，仅在缓存 `fingerprint` 是字符串且现代匹配未命中时才求值；`bridge.py` 两处改为传 lambda；`legacy_digest_candidates` 超过 8 个依赖时直接返回空集（保守重建），不做无界笛卡尔展开。指纹算法、现代缓存 generation 语义和产物身份不变。
- 证据：新增 `tests/unit/test_bug140_legacy_fingerprint_lazy.py`；合成探针由 0.415647 s/1024 候选降为 1.8 µs/0 次 legacy 调用；新算法缓存路径不调用生成器，旧缓存仍能匹配合法候选，伪造摘要不放行。定向 11 项 + 相关既有 126 项通过，Ruff 通过；`tools/dev_check.py` 全量 4286 项通过、`success=true`。

未验证：真实构建缓存的端到端启动计时（探针为合成依赖）；不改启动总预算。
