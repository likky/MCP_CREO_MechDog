类型：缺陷（验证工具链）

目标版本：0.37.1（PATCH；公开工具仍 111，无产品建模接口变更）

来源与关联：外部反馈原件已逐字节归档至 [test-mcp-capabilities-drift.md](../validation/feedback-0.35.8-2026-11-22/originals/test-mcp-capabilities-drift.md)（SHA256 `5944044677c36c089f182590881ee9710de44144390c57a7dd298e17698732ee`，清单见 [SOURCE_MANIFEST.json](../validation/feedback-0.35.8-2026-11-22/SOURCE_MANIFEST.json)）。同类前案 [BUG-138](BUG-138.md)（验收脚本硬编码工具数、失败被 TaskGroup 掩盖、门禁不覆盖）。计划：[2026-11-23 BUG-151 计划](../superpowers/plans/2026-11-23-bug151-test-mcp-capabilities-drift.md)。

## 问题或目标

已证实现象：在 `main@b54bff6`（0.35.8）执行文档推荐的 `tools\test_mcp.py`，必然在列工具与 schema 断言之后失败，`tools/test_mcp.py:71 KeyError: 'interpolation'`，exit 1，栈被 `ExceptionGroup: unhandled errors in a TaskGroup` 包住。本机 Windows x64 / Python 3.12.14 复现耗时 3.2 s，与是否连接 Creo 无关（失败发生在会话工具之前）。修复前原始输出见 `build/bug151_repro_before.txt`。

根因（已定位，非产品缺陷）：`creo_capabilities` 自 `fab8e0d`（FEAT-044/023/022/006/008）起默认 `detail="compact"`，`families` 变为精简索引，实测条目键集合只有 `{enabled, tool, limits_note}`；完整条目须 `detail="full", section="families"` 分页取回。`tools/test_mcp.py` 自 `0e92ab7`（DEV-002）后未再改动，仍按 0.4.2 之前“无参数返回完整文档”的旧契约断言 `families.loft_seed.interpolation`。

产品侧已核验完整：`detail="full", section="families", limit=50` 共 40 个族、2 页（首页 27 条并给出 `next_cursor`），`loft_seed` 位于第 2 页，12 个字段齐全，`interpolation=["straight","smooth"]`、`section_count_input_range=[2,20]`、`seed_section_count_must_match=true`，与脚本期望完全一致。

验证盲点：`tools/test_unit.py` 与 `tools/dev_check.py` 都不调用该脚本；BUG-138 建立的离线清单只含 `test_update_check`、`test_model_reconciliation`。脚本自 0.4.2 起跨 30+ 版本失效而无任何门禁报警，外部使用者按文档运行会误判产品能力回退。

目标：脚本在当前契约下通过；契约期望集中到单一可单测来源，使同类漂移在常规单元门禁中暴露。

## 0.37.1 实机验收与验证工具链收口（2026-11-23）

在 0.37.0（`main@3ce4ef5`）核对 0.35.8 外部反馈原件并执行实机验收时，发现三处遗留缺口并一并修复：

1. **实机模式必撞 `building_worker`**：`tools/test_mcp.py` 启动 `server.py` 后未等待 `creo_startup_status` 即直调 `creo_session_status`，在后台协调器仍处于 `building_worker` 时必然 `AssertionError` 且被两层 `ExceptionGroup` 包装。同步查出 `tools/mcp_readiness.py` 漏列 `creo_startup.ACTIVE` 中的 `connecting`（BUG-139）与 `waiting_for_channel`。现已改为引用 `creo_startup.ACTIVE`、在实机模式调用 `wait_for_startup`、显式打印异常回溯、自动创建 `build/` 目录、加入 `cancelled` 终态与 `detail="full"` 分页 `result_entries` 兜底。
2. **脚本纳入自动离线门禁**：`tools/test_mcp.py` 新增 `--offline`（内部 `--serve-offline` 隔离 `startup.start` 与 `updates.start`，不拉起 Creo、不触网，走真实 stdio 传输），加入 `tools/dev_check.py` 的 `OFFLINE_ACCEPTANCE_SCRIPTS`（三项全绿，`test_mcp --offline` 2.14 s）。
