# BUG-143：merge/mirror/fill 结果缺少 quilt_id，solidify 对 merge label 必然误引用

分类：**部分交付 0.35.6 子项**（0.35.6 交付固体镜像挂死根因与创建前拒绝；闭合锥面 trim 与其他非圆柱形态未排期）

类型：缺陷

优先级：P1

状态：部分交付 0.35.6 子项（0.35.0 子项、0.35.2 镜像崩溃防护与标签实机、0.35.3 非圆柱跨作业链路均已发布；0.35.6 复现固体特征镜像挂死并定位 `PRO_E_MIRROR_REF_ITEMS` 不接受 `PRO_FEATURE`，契约与原生改为创建前拒绝全部 feature 引用并实机复验；闭合锥面 trim 受面积测量限制，与其他非圆柱形态未排期）

目标版本：0.35.0（子项已交付）；0.35.2（镜像防护与标签实机已交付）；0.35.3（非圆柱链路与保存闭环证据已交付）；剩余未排期

来源与关联：[0.33.0 反馈归档](../validation/feedback-0.33.0-2026-11-21/SOURCE_MANIFEST.json) `surface-worker.md` P0-1、P2-9；关联 BUG-120、BUG-115、原生 surfaces 与结果投影。

## 问题或目标

0.32.0 回执只给 merge feature_id，合并后的目标 quilt 仍关联原始特征，使用 `{kind:"quilt_feature",label:<merge label>}` 实体化会报 ProError -4；mirror/fill/merge 又不直接返回 quilt_id，调用方只能再扫描并猜测。目标是让公开回执直接提供经过实测核对的结果 quilt_id，并使 merge/mirror/trim 结果 label 能正确解析到实际目标 quilt，或在提交前给出可操作的明确拒绝及可用 quilt id；不得靠静默选择最近 quilt 猜测。

## 范围

包含 mirror、surface_fill、quilt_merge 的结果标识及 solidify 引用解析/诊断，保留现有 `{kind:"quilt",id:N}` 路径。不改变 merge 消耗关系、闭合语义或 single-channel/revision 保护；closure -62 的独立语义由 DEV-098 核对。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python + 原生文本回归 | 引用与结果投影单测 | 返回确定 quilt id；无唯一结果时不编造；merge label 不再落到 feature 反查失败 |
| 本机 Creo 10 / 匹配 SDK | fill→merge→solidify 原子计划及分步对照 | merge label 与 quilt id 引用行为符合契约，实体有效、保存重载 true；失败可回滚 |
| 本机 Creo 10 / 匹配 SDK | mirror/fill/merge 回执 | quilt_id 与 `inspect_model(section="quilts")` 一致，无需按 bbox 猜测 |

## 实现与证据

2026-11-21 实现并实机验收（本机 Creo 10.0.0.0，release 42，worker `277cbac5…`）：

- `native/surfaces.cpp`：`surface_fill` 只有在 `ProQuiltInit` 验证唯一 quilt 后才登记 `quilt_id`；`solidify` 对 `merge`/`mirror`/`surface_trim` 标签先用原生实测记录（merge 用 `quilt_id`、trim 用 `result_quilt_id`）解析并再次 `ProQuiltInit` 校验，同计划 mirror 仅在 feature→quilt 唯一归属时接受，否则明确拒绝并附候选，不按 bbox/面数/顺序猜。
- `native/quilt_query.h`：`resolve_quilt_reference` 的 `quilt_feature` 分支先查本作业别名记录的实测 quilt id，校验通过后使用；随后才回退到 feature 反查。修复了第二次 `quilt_merge` 用第一次 merge 标签时的 `-4`。
- `src/creo_mechdog/operation_results.py`：仅对 committed 的 mirror/fill/merge 投影原生实测 id 或 inspection 中唯一 feature 归属；冲突/缺失/多匹配省略；`compact_sections.py` 保留 `quilt_id`。
- **实机正证据**：`merged_closed_plan`（tube + 两封盖 + 两次 merge + `solidify(reference={kind:"quilt_feature",label:"merge_closed_result"})` 同计划）作业 `bcc2c0d5802d4cdfbb5bc99f2c410da9` `succeeded`，两份 merge 回执 `quilt_id=result_quilt_id=71`，`solidify.target_quilt_id=71`、体积 785.3981633974481 mm³（=π·5²·10）、`saved_file_reloaded_and_verified=true`；fill 回执分别给 `quilt_id` 95/114。另 `{kind:"quilt",id:N}` 路径由 `test_surface_chain --case solidify` 复跑全项通过（run `20261121-022012-337500`）。
- **实机失败语义**：fill 标签被 solidify 引用时解析成功，仅因 quilt 开放而按 `quilt_is_open` 拒绝（作业 `975f8b2ce…`），不再报 -4。
- 离线：新增 `tests/unit/test_bug143_quilt_results.py` 10 项；全量 4286 项通过。

跨作业边界：标签别名按作业持有，跨作业应使用回执 `quilt_id`（文档与 capabilities 已说明）。未验证：mirror 标签的实机消费、trim 结果标签链、非圆柱组合。另注：`tools/test_surface_chain.py --case merge` 的首个“相邻共面 fill 合并”在本机 Creo 10 仍在建特征时失败（既有共面 JOIN 限制，capabilities 已披露），与本卡的标签解析无关；本卡实机证据取自已成功的闭合圆柱计划。

## 固体特征镜像挂死（2026-11-21 实机复现，已改为创建前拒绝）

本批 T06 的“固体镜像复验”**未通过**：镜像实体特征会让 Creo 阻塞在原生创建调用里。原因与处置如下。

- 现场：全新 Creo 10 会话（`toolkit_code=0`），先建实体块（10×20×10，体积 1999.9999999999998 mm³，保存重载 true，模型 `40b6881df15041898ff253fa41c3a900`）。
- 复现计划：`{"op":"mirror","label":"block_mirror","plane":{"kind":"datum_plane","axis":"x"},"references":[{"kind":"feature","label":"block"}],"keep_original":true}`。
  - 第一次（作业 `c1a1dd33f9de4d979474f19eca8b9295`）：330 s 仍 `running`、`stage=mirror:block_mirror`。
  - 第二次（作业 `7b7be35e13fd42b5bfca92f4d36250ae`）：240 s 轮询只见 `queued → connect → mirror:block_mirror`，无进一步进展。
- 原生停点：两次 `native.log` 最后一行都是 `ProArrayAlloc(1, sizeof(ProFeatureCreateOptions), 1, (ProArray *)&opts)=0`，即进入 `ProFeatureCreate` 后没有返回。
- 不是“算得慢”：`xtop.exe` 的 CPU 在 6 s 内 470.578 → 470.593，窗口 `Responding=True`，是阻塞等待而非计算。
- 后果：单通道被占（`connection_state=busy`）；进程回收后同一会话变为 `toolkit_code=-38`、`worker_exit_code=20`，会话一起不可用；模型记录留下 `pending_job` 指向该作业、`revision=1`、`part_file` 仍是已验证的磁盘基线。
- 与 0.35.2 防护的区别：那次是**曲面特征引用**在 `ProFeatureCreate` 处崩溃，已在 `generic_mirror` 前置拒绝；本次是**实体特征引用**，通过前置检查后挂死。

**根因**：`ProMirror.h` 的 `PRO_E_MIRROR_REF_ITEMS` 只列 `PRO_CURVE`、`PRO_COMP_CRV`、`PRO_AXIS`、`PRO_QUILT`、`PRO_DATUM_PLANE`、`PRO_CSYS`、`PRO_POINT`、`PRO_PART`，并明确写明 `PRO_FEATURE` 类型的镜像项自 Wildfire 2.0 起不受支持。旧实现把 `{kind:"feature"}` 解析成 `PRO_FEATURE` selection 塞进该元素，属于未定义行为：曲面特征会崩溃，实体特征会挂死。

**处置**（本批已实施，未随任何版本发布）：

- `native/advanced.cpp` `generic_mirror`：在 `create()` 之前拒绝**全部** `feature` 引用（不再区分曲面/实体），两条文案分别给出可行路线——曲面特征指到 `creo_inspect_model(section="quilts")` 的 `{kind:'quilt',id:N}`，实体特征指到 `{kind:'part'}`；两条都声明“未创建、未复制几何、未改 revision”。
- `src/creo_mechdog/schema.py` `MirrorOp`：从允许种类中移除 `feature`，使计划在提交前就被拒绝，不启动 worker。
- `src/creo_mechdog/capabilities.py`：`mirror` 的 `scope`/`limits` 改为“曲线/轴/quilt/基准面/坐标系/点/整体零件”，并写明 feature 项会挂死主线程。
- 源回归：`tests/unit/test_bug143_quilt_results.py::test_mirror_refuses_every_feature_reference_before_create`（两条分支、均在 `create(root)` 之前）、`tests/unit/test_v021_validation.py::test_mirror_references_take_geometry_or_the_whole_part`。

**实机复验**（`build/live_bug143_mirror_guard2.py`，报告 `build/live_bug143_mirror_guard.json`）：

| 用例 | 结果 |
| --- | --- |
| 实体特征引用 `{kind:"feature",label:"block"}` | `creo_execute_plan` 直接返回契约错误 `operations[2]: Toolkit mirror accepts curves, axes, quilts, datum planes, coordinate systems, points or the whole part; a feature reference is not a mirror item and hangs Creo…`；没有生成作业（`feature_job=null`），会话前后均 `connected=true`、`toolkit_code=0` |
| 推荐的 `{kind:"part"}` 路线 | 作业 `dbdd127fd1794749822df2eaaa7f536d` `succeeded`（`stage=verified`，10 s 内完成）；体积 4000.0000000000005 mm³（原块 1999.9999999999998 的两倍）、`has_solid=true`、`saved_file_reloaded_and_verified=true`；会话仍 `toolkit_code=0` |

离线：`tools/test_unit.py --report build/unit_test_final3.json` 4,334 项、0 失败、0 错误、6 跳过（受测指纹 `710836cd…`）；`tools/dev_check.py --skip-unit --work-item BUG-143` `success=true`（Ruff 0 发现、0 文件待格式化，离线 stdio 验收通过）。

未验证：其他实体特征类型（hole/round/shell）作为 feature 引用（现已统一拒绝，不再进入原生）、`keep_original=false` 的整体镜像、其他基准面。
