# BUG-157：看门狗观察 native.log 并开放装配基线恢复

分类：**开发中**。优先级 P0（0.35.5 反馈 P0 批次）。

来源为 [0.35.5 原始反馈](../validation/feedback-0.35.5-2026-11-22/originals/geometry-and-assembly-p0.md) §九、§十五、§十八。现场作业 `77794599…`/`33482afa…` 被看门狗杀死后，装配在 `creo_reconcile_model` 中没有任何可用动作，模型永久锁死。

根因：
- `generic_bridge.py` 的看门狗只统计 `worker.log`；原生进度写在 `native.log`，长任务 `log_bytes` 恒为 0，达到停滞预算即被杀。
- `reconciliation.py` 的 `supported` 只含 part/sheetmetal，装配恢复动作被一票否决；`abandon_new` 只对未提交的新装配开放。
- 原生恢复对所有动作做两次完整 inspection 与深度比较，`RecoveryDeadline` 固定 90 s；高边数零件或 269 组件装配必然超时。
- 装配的组件依赖让 `recovery_dependency_free()` 恒为 false。

范围：
- 看门狗同时观察 `worker.log` 与 `native.log`，任一增长刷新进度，停滞证据记录两者字节数。
- 恢复准入允许装配 `restore_baseline`，要求基线已验证且当前 `part_file` 身份一致；`accept_live` 的依赖检查改为“依赖位于模型输出目录或受管 `models` 根”。
- 原生新增内部 `verify_mode=identity`：重载 + 重新生成后只核对模型名/类型/单位、特征数和体积，跳过完整 inspection；回执明确 `full_inspection_verified=false`。
- 新增 `recovery_phase_seconds`（默认 300，30–900），仍受作业总预算约束。

验收：`native.log` 持续增长场景不再误杀；保存过的装配在 `unknown_outcome` 下 `restore_baseline` 可用且成功；6428 边零件 `identity` 恢复在预算内完成；受管目录外依赖明确拒绝。未验：Creo 9/12、原始 269 组件现场、外部 WorkBuddy。
