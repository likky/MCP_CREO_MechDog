# BUG-133：显式旋转矩阵容差在 Python 与原生端不一致

分类：**部分交付 0.30.0**（软件层修复并通过离线回归，Creo 实机待验收）。

类型：缺陷。优先级：P1。状态：部分交付 0.30.0（软件层已修复并经离线回归，Creo 实机待验收）。目标版本：0.30.0。

来源：[DEV-092](DEV-092.md) 对 Creo 13.4 / MCP 0.26.0 装配评估的离线核对。报告建议为六位小数矩阵传 `rotation_tolerance=1e-5`，本次发现该建议只通过 Python 准入，原生仍会拒绝。

## 现象与原因

- `src/creo_mechdog/schema.py` 的 `AssemblyPose.matrix_tolerance_valid` 按调用方的有效容差校验。
- `native/assembly_pose.h` 的 `assembly_rigid_transform` 调用 `assembly_rotation_admission` 后，仍以固定 `assembly_admission_tolerance() == 1e-6` 拒绝；原生代码没有读取 `rotation_tolerance`。
- 创建组件、重定位和失败回执重算共用该 helper，因此存在 Python 已接收、原生再拒绝的确定性分歧。尚未连接 Creo 重现公开工具终态，不据此断言 Creo 内核会接受放宽后的输入。

最小独立输入（合成的 28° 六位小数算例，**不是**报告缺失的 P03 原始矩阵）：

```json
{"op":"component_placement","component":"probe","rotation_matrix":[[0.882948,0.469472,0],[-0.469472,0.882948,0],[0,0,1]],"rotation_tolerance":0.00001}
```

`max |R R^T-I| = 1.1294880000178864e-6`。本次 Python 准入通过且矩阵保持原值；相同矩阵在默认 `1e-6` 下拒绝，报错显示 `1.129488e-06`。本次 SDK 无关 C++ probe 调用生产 helper，在同样显式 `1e-5` 下仍拒绝，已确认跨层分歧；构建/运行均退出 0，其中运行 0 代表捕获预期拒绝，并非修复通过。实施与实机范围见 [处理计划](../superpowers/plans/2026-11-19-dev092-creo13-assembly.md)。

## 范围与验收

1. 统一 Python、原生 helper、直接原生输入校验和回执的有效容差；默认保持 `1e-6`，不自动转置、重正交或修改输入数值。
2. **实施前待冻结的边界**：当前 Python 只要求容差为正且有限，超大值可能放行反射/缩放。需先定义允许上限或独立刚体判定，再同步两层；该决策可能收紧现有 Python 输入范围，要明确兼容性影响，不能仅让原生照搬任意正数。回归覆盖创建/重定位、缺省/显式容差、布尔/非有限/非正数、超限非正交、反射及默认行为；接收与报告使用相同规则。
3. 在 SDK 无关的 `tests/native/test_assembly_pose.cpp` 增加失败用例，使用 `tools/test_assembly_pose.py` 验证生产 helper，不加载 Toolkit。
4. 修改后运行专项及 `tools/dev_check.py --work-item BUG-133`。原生执行器构建和 Creo 几何/保存重载验收须用户当次明确确认。若内核仍拒绝，准确报告阶段/API/原始错误，不自动修复矩阵或宣称该精度可建模。

## 冻结的容差契约（2026-11-19，实施前决策）

- 默认准入容差保持 `1e-6`，为唯一公开值；`rotation_tolerance` 省略或 null 时取该值。
- 显式容差允许范围收紧为 `0 < t ≤ 1e-3`（`MAX_ADMISSION_TOLERANCE` / `assembly_max_admission_tolerance`）。依据：准入条件同时要求 `max |R*Rᵀ−I| ≤ t` 与 `|det−1| ≤ t`；反射的 `|det−1| = 2`、缩放基的偏差远大于 `1e-3`，因此上限以内的任何值都不会把非刚体变换放进通道，而 `1e-3` 已是上报六位小数算例（`1.1e-6`）的百倍余量。上限之外不再描述“四舍五入”，且会让原本被拒的反射/缩放通过。
- 兼容性影响：此前 Python 只要求正有限（`Positive` 上限 100000），`rotation_tolerance > 1e-3` 是被接受的；现在两层一致拒绝，属明确收紧。没有既有实机调用依赖该区间，拒绝时给出可操作的原文。
- 只对显式 `rotation_matrix` 生效；Euler 输入带 `rotation_tolerance` 直接拒绝，避免无效字段静默生效。
- 两层同值：Python `validate_tolerance` 与原生 `assembly_tolerance_from_json` 使用同一上下界；原生成功回执发布 `rotation_tolerance`（有效值）与 `input_rotation_convention`，失败回显发布 `matrix_convention`/`admission_tolerance` 并按同一门槛测量。

## 修复内容（2026-11-19，软件层）

- `native/assembly_pose.h`：`assembly_rotation_admission(rotation, tolerance)` 接受有效容差；新增 `assembly_max_admission_tolerance`、`assembly_tolerance_from_json`、`assembly_effective_tolerance`、`assembly_input_convention` 与高精度数字格式（`%.9g`，取代 `std::to_string` 的六位小数）。`assembly_rigid_transform` 从同一 op 读取 `rotation_tolerance`，创建、重定位与失败回算共用。
- `src/creo_mechdog/rotation_admission.py`：新增 `MAX_ADMISSION_TOLERANCE`、`validate_tolerance`、`tolerance_text`；`admission_status(rotation, tolerance)` 与 `PRECISION_ADVICE` 使用有效容差。
- `src/creo_mechdog/schema.py`：`AssemblyPose.matrix_tolerance_valid` 走同一校准函数；`_rotation_matrix` 按有效容差计算残差与 det。
- `src/creo_mechdog/failure_context.py`：`_precision`/`_matrix_block`/`_native_matrix` 携带并沿用有效容差，不再固定 `1e-6`。
- `native/advanced.cpp`、`native/generic.cpp`、`src/creo_mechdog/job_projection.py`：回执与失败投影发布 `input_rotation_convention`、`rotation_tolerance`、`matrix_convention`、`admission_tolerance`。
- 回归：`tests/native/test_assembly_pose.cpp`（28° 矩阵默认拒绝 / `1e-5` 接受且逐值不变 / `1e-7` 拒绝 / 超过 `1e-3` 与反射被拒 / 非法容差拒绝 / `1e-3` 边界接受）、`tests/unit/test_rotation_admission.py`（创建与重定位两条分支、上限、非法值、两层共享常量）。
