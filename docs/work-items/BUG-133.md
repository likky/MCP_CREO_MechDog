# BUG-133：显式旋转矩阵容差在 Python 与原生端不一致

类型：缺陷。优先级：P1。状态：待开发（台账分类：仍需修复）。目标版本：未排期。

来源：[DEV-092](DEV-092.md) 对 Creo 13.4 / MCP 0.26.0 装配评估的离线核对。报告建议为六位小数矩阵传 `rotation_tolerance=1e-5`，本次发现该建议只通过 Python 准入，原生仍会拒绝。

## 现象与原因

- `src/creo_mechdog/schema.py` 的 `AssemblyPose.matrix_tolerance_valid` 按调用方的有效容差校验。
- `native/assembly_pose.h` 的 `assembly_rigid_transform` 调用 `assembly_rotation_admission` 后，仍以固定 `assembly_admission_tolerance() == 1e-6` 拒绝；原生代码没有读取 `rotation_tolerance`。
- 创建组件、重定位和失败回执重算共用该 helper，因此存在 Python 已接收、原生再拒绝的确定性分歧。尚未连接 Creo 重现公开工具终态，不据此断言 Creo 内核会接受放宽后的输入。

最小独立输入（合成的 28° 六位小数算例，**不是**报告缺失的 P03 原始矩阵）：

```json
{"op":"component_placement","component":"probe","rotation_matrix":[[0.882948,0.469472,0],[-0.469472,0.882948,0],[0,0,1]],"rotation_tolerance":0.00001}
```

`max |R R^T-I| = 1.1294880000178864e-6`。本次 Python 准入通过且矩阵保持原值；相同矩阵在默认 `1e-6` 下拒绝，报错显示 `1.129488e-06`。本次 SDK 无关 C++ probe 调用生产 helper，在同样显式 `1e-5` 下仍拒绝，已确认跨层分歧；构建/运行均退出 0，其中运行 0 代表捕获预期拒绝，并非修复通过。实施与实机范围见 [处理计划](../superpowers/plans/2026-11-19-dev092-creo13-assembly.md)。

## 范围与验收

1. 统一 Python、原生 helper、直接原生输入校验和回执的有效容差；默认保持 `1e-6`，不自动转置、重正交或修改输入数值。
2. **实施前待冻结的边界**：当前 Python 只要求容差为正且有限，超大值可能放行反射/缩放。需先定义允许上限或独立刚体判定，再同步两层；该决策可能收紧现有 Python 输入范围，要明确兼容性影响，不能仅让原生照搬任意正数。回归覆盖创建/重定位、缺省/显式容差、布尔/非有限/非正数、超限非正交、反射及默认行为；接收与报告使用相同规则。
3. 在 SDK 无关的 `tests/native/test_assembly_pose.cpp` 增加失败用例，使用 `tools/test_assembly_pose.py` 验证生产 helper，不加载 Toolkit。
4. 修改后运行专项及 `tools/dev_check.py --work-item BUG-133`。原生执行器构建和 Creo 几何/保存重载验收须用户当次明确确认。若内核仍拒绝，准确报告阶段/API/原始错误，不自动修复矩阵或宣称该精度可建模。
