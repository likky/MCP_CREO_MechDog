# BUG-134：resident_panel 作业因 ProMdlCurrentGet 返回 -8 失败，面板块也不说明目标模型

分类：**部分交付 0.33.0**（本机 Creo 10 实机主场景通过：无 -8、`model_name` 正确、几何与保存重载通过；Creo 12.4 与 `PANEL_MODEL_UNAVAILABLE` 失败路径未验）。

类型：缺陷

优先级：P1

状态：待验收（2026-11-20 本机 Creo 10 实机主场景通过；Creo 12.4 与失败路径未验）

目标版本：0.33.0（候选）

来源与关联：0.31.1 三份反馈中的“球鼻艏面板 -8”与交付记录门禁报告；关联 [BUG-120](BUG-120.md)、FEAT-065、[DEV-095](DEV-095.md)。

分类依据：待验收——离线实现与单元测试已完成，本机 Creo 10 主场景实机通过；Creo 12.4 复测与 `PANEL_MODEL_UNAVAILABLE` 失败路径仍缺。

## 问题或目标

worker 通过 `ProEngineerConnect` 异步连接 Creo，会话中没有用户当前激活上下文，`ProMdlCurrentGet` 恒返回 `PRO_TK_BAD_CONTEXT`（-8）。`resident_panel` 在打开边界混合对话框之前就因此失败，作业无法进入面板流程。

同时暴露两个可观测性缺口：

1. 提交回执的面板块没有 `model_name`，用户无法确认作业指向哪个模型。
2. 错误文案没有指出应先显示目标模型，也没有指向 `creo_capabilities(detail="full", section="runtime")` 的前置条件说明。

## 范围

1. `native/panel_run.h`：优先使用 `ProMdlInit` 解析出的 board（`native/geometry.cpp` 中的静态全局）；board 为空才回退 `ProMdlCurrentGet`，仍失败则抛 `PANEL_MODEL_UNAVAILABLE`。
2. 新增 `ProMdlMdlnameGet` 校验 `wanted_model`，避免面板落到其他模型。
3. 打开面板前执行 `ProMdlDisplay` → `ProMdlWindowGet` → `ProWindowCurrentSet`，并把 `model_source`、`current_model_code`、`display_code`、`window_query_code`、`window`、`current_window_code` 写入 `panel_preopen` 并调用 `stage_preopen()`，失败时随回执返回实际码值。
4. `generic_bridge.py` 面板块补 `model_name`（回执投影同步，CONTRACT 不变）。
5. `server.py` 的 `creo_surface_loft` docstring 改为指向 `creo_capabilities` 的 runtime 分区。
6. 不包含：不新增公开“显示/激活模型”工具——那会改变公开工具数与能力清单，且离线不可验证。
