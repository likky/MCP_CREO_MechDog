## 修复内容

1. `native/recovery_deadline.h`：超时触发 `ExitProcess(31)` 前除 `native_checkpoint.json` 外同步写出最小 `native_result.json`（`success=false`、`delivery_complete=false`、`completion_stage="recovery_phase_timeout"`、`failure_phase="native_worker_started"`、`phase_budget_seconds`、`toolkit_code=-1` 与包含 `verify_mode='identity'` / `budget_seconds` / `abandon_unknown_recovery` 指引的 `message`）；`reconciliation._native()` 保持 `unknown_outcome` 保护并在报错中直接披露 `recovery_phase_timeout (<N> s)`。
2. `native/generic.cpp`：`reconcile_native` 在 `action == "restore_baseline"` 的 `verify_mode == "full"` 分支复用已重载再生并校验通过的 `before` 快照，跳过此前无 save/reload 间隔的第二次重复 `inspection()`；原生 `recovery_phase_seconds` 钳位上限由 `900.0` 提升至 `1800.0`。
3. `src/creo_mechdog/reconciliation.py`、`server.py`：`RECOVERY_PHASE_MAX_SECONDS` 提升至 `1800`；自适应下限同时按 `edges`（`120 + edges // 15`）、`features`（`120 + features // 2`）、`surfaces`（`120 + surfaces // 4`）取最大下限（474 特征自动抬至 357 s，6428 边保持 548 s）；当 `recovery_pending` 作业已处于终态（`failed`/`unknown_outcome`/`aborted`/`cancelled`）时，`_recovery_wait()` 返回 `state="terminal_unconfirmed"` 并明确提示不要继续轮询 `creo_get_job`，改调 `restore_baseline` 或 `abandon_unknown_recovery`。
