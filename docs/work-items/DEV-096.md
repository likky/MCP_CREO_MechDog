# DEV-096：发布记录门禁只校验 previous_release_commit 形状，未交叉核对上一版本提交与标签

分类：**部分交付 0.33.0**（交叉校验与标签核对已实施并由本版发布记录实跑通过；负例复核与历史记录回归未验）。

类型：工程整理

优先级：P2

状态：待验收

目标版本：0.33.0（候选）

来源与关联：0.31.1 反馈“发布记录门禁盲点”；关联 [DEV-094](DEV-094.md)、`docs/releases/`、`docs/validation/RELEASE-*.md`。

分类依据：待验收——离线实现与单元测试已完成，尚缺对现有发布记录的实跑校验确认。

## 问题或目标

`src/creo_mechdog/release_integrity.py` 对 `docs/releases/<ver>.json` 的 `previous_release_commit` 只做 40-hex 形状校验，无法发现它指向了别的提交。`RELEASE-<ver>.md` 中“上一版本 … 提交 …”的文本，与 JSON、git 标签三者之间没有交叉校验，门禁因此存在盲点。

## 范围

1. `_delivery_snapshot` 返回值增加 `previous_release_commit`。
2. 新增 `_previous_commit_problems(text, snapshot, origin)`：校验 `RELEASE-<ver>.md` 中“上一版本”行的 40-hex 与 JSON 一致。
3. 新增 `_tag_commit_problems(version, root)`：仅在 `root/.git` 存在时用 `git -C root rev-parse v<previous>^{commit}` 核对标签指向。
4. 接入 `_records_problems` 的 `RELEASE-<version>.md` 分支与 `validate_release_records` 的 tree 分支。
5. 不包含：不改变标签与附件的发布流程本身。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | `tests/unit/test_release_integrity.py` 的 `PreviousReleaseCommitSemanticsTests` | 四例通过：一致、JSON 与 Markdown 不一致、标签指向不符、无 `.git` 时跳过标签核对 |
| Windows / Python / 现有记录 | 对现有已发布记录跑一次校验 | 保持通过，不出现新增误报 |
| Windows / Python / 构造错误 | 把 `previous_release_commit` 改成其他提交号 | 返回可读问题码，指出具体文件与不一致字段 |

无原生代码，不需要 Creo 实机。
