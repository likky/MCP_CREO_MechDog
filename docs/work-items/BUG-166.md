# BUG-166：恢复预算自适应/可配、跨会话恢复解死锁、`abandon_unknown_recovery` 出口与 `recovery_pending` 准入口径

- 类型：缺陷
- 优先级：P1

分类：**已有修复但待验收**（0.39.0 已交付并完成本机 Creo 10.0.0.0 实机验收；原始 6428 边 M113 P05 模型、Creo 9/12 与 WorkBuddy 黑盒未验）

- 目标版本：0.39.0（MINOR）

来源：[0.35.5 原始反馈](../validation/feedback-0.35.5-2026-11-22/originals/geometry-and-assembly-p0.md) §十五、§十八，以及 [0.36.0 反馈原件 §三（问题 B）、§四（问题 C）、§十一](../validation/feedback-0.36.0-2026-11-23/originals/upgrade-session-and-recovery-deadlock.md)。

## 修复内容

- `generic_bridge.py`：`recovery_pending` 阻塞时上报 `blocking_operation="recovery_pending"`，在 `owner_snapshot` 中同时给出 `pending_job` 与 `recovery_pending`，并明确提示 `expected_pending_job_id=null`；装配源取用（只检查 `pending_job`）保持不变。
- `src/creo_mechdog/reconciliation.py` 与 `server.py`：
  1. `session_fingerprint` 仅在 `action="accept_live"` 或当次 `inspect(live=True)` 取得新会话证据时写入 `choice`；`restore_baseline`、`abandon_new`、`accept_saved` 在 `live=False` 时不再绑定已死亡旧会话的 `session_fingerprint`（原生仍校验 `loaded && !owned` 与基线文件 SHA256/几何）。
  2. 新增 `abandon_unknown_recovery` 动作（需 `confirm_unknown_recovery=true` + 所有已记录 owner 停止 + `recovery_pending` 作业已到终态 `failed`/`unknown_outcome`/`aborted`/`cancelled` + 如有 `part_file` 须基线哈希通过）：仅清 `recovery_pending` 并在 `pending_job=null` 时恢复 `ready`，不推进 revision、不改磁盘文件，审计记录标注 `disk_state_verified=false`、`session_state_verified=false`。
  3. 为 `creo_reconcile_model` 新增可选 `budget_seconds: int | None`（30–900 s）与 `verify_mode: Literal["identity", "full"] | None`；默认 `recovery_phase_seconds` 按模型已记录边数自动抬高下限（`min(900, max(base, 120 + edges // 15))`，6428 边自动 548 s）。
