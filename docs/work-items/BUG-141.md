# BUG-141：已退出 Creo 进程被计入身份不确定并阻断启动

分类：**部分交付 0.35.0，剩余待验收**

类型：缺陷

优先级：P1

状态：部分交付 0.35.0，剩余待验收（已发布；已退出条目判断与身份冲突保护离线通过；真实僵尸进程现场未验）

目标版本：0.35.0

来源与关联：[0.33.0 反馈归档](../validation/feedback-0.33.0-2026-11-21/SOURCE_MANIFEST.json) `startup-chamfer.md` P2；关联 `creo_startup.py`、BUG-139。

## 问题或目标

外部 0.32.0 现场中，`HasExited=True`、无线程/句柄的进程条目仍被 `inventory()` 标为 `uncertain`，使协调器持续 `selection_required`。当前版本需核对进程快照字段与异常分支：仅对能够明确确认已经退出的条目忽略其身份不确定性；仍在运行、权限不足或状态不可知的进程必须继续保护，不能用 `selected`、allowlist 或强制 ready 绕过。

## 范围

包含已退出进程识别、inventory 回归及启动选择路径测试。不包含结束进程、清锁、终止未知会话或放宽多实例/权限不足保护。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | `tests/test_creo_startup.py` 及新增回归 | 明确 exited 条目不产生 uncertain；活跃、无权限、信息不全条目仍按原保护处理 |
| Windows / Python | selected 与多实例组合测试 | 不因用户选择而吞掉真实身份冲突 |
| Windows / Python | `tools/dev_check.py` | 无新增问题 |

真实僵尸对象不能由单元测试证明可删除；若本机无同型现场，实机项记未验证。

## 实现与证据

2026-11-21 按当前 0.34.0 源码修复（离线，未实机）：

- `creo_startup.inventory()` 在 `ProcessIdToSessionId` 失败时不再一律标记 `uncertain`：改为调用 `process_identity()`，只有它确认 PID 不存在（87/1168）或 `GetProcessTimes` 报告已退出时忽略；活跃进程、权限不足（OSError）或状态不可知仍标记 `uncertain`。
- `require_ready()` 在 `state="selection_required"`（真实身份冲突）时不再被 `_force_ready` 或 recent 探针绕过。
- 证据：新增 `tests/unit/test_bug141_exited_process_inventory.py`；退出条目 `uncertain` 由 True 变 False，活跃/无权限/信息不全仍保护，selected 与多实例组合仍拒绝。全量 4286 项通过。

未验证：真实僵尸进程对象与外部 Windows 现场的“只能重启”现象；不结束进程、不清锁、不放宽多实例保护。
