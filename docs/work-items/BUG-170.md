## 2026-11-25 启动探针暂态复核

0.44.0 P6 报告首次 `creo_startup_status` 见 `toolkit_code=-4`、worker 退出码 20，紧接着会话连接成功。本批用 Windows x64 / Creo 10.0.0.0 对照暂态、持续不可达和主动超时。验收覆盖同一启动尝试内的有界重探、终态诊断、原始错误、单通道及禁止自动重复拉起。

本机 Creo 10 C TOOLKIT 的 `ProToolkitErrors.h` 将 `-4` 定义为 `PRO_TK_E_NOT_FOUND`，将 `PRO_TK_BAD_CONTEXT` 定义为 `-8`。以下原登记中的旧诊断名称保留作历史记录。

修复前通过真实 stdio 与 Creo 10 worker 受控复现 `-4 / exit 20` 随后 `0 / exit 0`。首个探针临时收到不存在的会话目标，下一探针恢复正常自动发现。工具把首错留在通用等待状态，启动下一探针时丢掉该错误快照。存量会话盘点发现未保存的对象，因此受控测试沿用当前 Creo 进程。探针环境和协调目录仅在测试子进程内设置。基线报告 `build/bug170-startup-baseline.json`（SHA256 `e8957a81efce3df69bb5fab9546a90b22b2cd366803ff5b16f017cff3e14acbc`）。 [PTC ProEngineerConnect 返回码](https://support.ptc.com/help/creo_toolkit/protoolkit_pma/r2027/usascii/creo_toolkit/api/dita/497.html)

修正后，自动发现期间的 `-4` 显示为 `waiting_for_connection / session_not_ready`，保留原始回执供查询。协调器继续在原截止时间内重探，直连及 Explorer 复核都使用剩余预算。持续查询失败时，以已完成的至少两次失败和现有进程为依据在终态提示持续不可达，最后一次探针超时时也保留 `last_lookup_failure`。单次查找失败随后遇到截止时间仅报 `startup_timeout`。活动期间 `creo_session_status` 返回启动快照，`live_probe.performed=false`。已有的显式会话选择、`force_new_session`、Toolkit 通道和未知任务保护仍按原入口执行。

## 0.39.0 历史记录

## 现象与根因

1. MCP 升级或重建 worker 后，旧 Creo 进程仍在运行，新 worker 探测返回 `toolkit_code=-4`（`PRO_TK_BAD_CONTEXT` / `not_found_or_unreadable`）。
2. `creo_startup.py::_drive()` 看到 `current["processes"]` 非空即永远跳过 `launch_creo()`，`creo_startup_status(retry=true)` 只能等到 `startup_timeout` 并返回笼统的 `"Existing Creo processes were preserved"`，没有区分“旧进程存活但上下文不可达”。
3. 工具侧除人工关闭 Creo 外无显式新建会话开关，且 `session_candidates` 未明确标注 `diagnostic_only`。

## 修复内容

- `creo_startup.py` 与 `server.py`：
  1. 新增 `_stale_session_diagnosis()`：当匹配安装目录的 Creo 进程仍在运行且探针返回 `toolkit_code=-4` / `not_found_or_unreadable` / `PRO_TK_BAD_CONTEXT` 时，在 `creo_session_status` 与 `creo_startup_status` 中输出 `stale_session_detected=true`、`diagnosis="stale_session_needs_restart"` 与排序第一的 `next_steps`（“关闭旧 Creo 后重试”或“显式 `retry=true, force_new_session=true`”）。
  2. 为 `creo_startup_status` 新增显式可选参数 `force_new_session: bool = False`（必须配合 `retry=true`，禁止与 `session_id`/`clear_session_id`/`force_ready` 同用，绝不自动关闭旧 Creo 进程）：在存在不可达旧进程时允许显式拉起新会话并递增 `launch_attempt`，记录 `forced_new_session=true`。
- `src/creo_mechdog/session_candidates.py`：顶层新增 `diagnostic_only=true`、`selectable_by_pid=false`，明确 PID 不可作为 `session_id` 选定。

## 验收证据（2026-11-23）

- 单元测试：`tests/unit/test_feedback0360_fixes.py::Bug170StaleSessionAndForceNewTests` 5/5 通过（`-4` 诊断触发/静默、`force_new_session` 参数互斥、`_drive()` 不带开关保旧并报 `stale_session_needs_restart` / 带开关拉起新会话并连上、`session_candidates.diagnostic_only`），及 `tests/test_creo_startup.py`、`tests/unit/test_feat072_session_selection.py`、`tools/test_mcp.py --offline` 全通过。
