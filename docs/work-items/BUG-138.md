# BUG-138：独立验收脚本硬编码旧工具数（82/84），跨版本必失败且被 TaskGroup 掩盖

分类：**部分交付 0.34.0**

类型：缺陷

优先级：P1

状态：部分交付 0.34.0（已实现并离线单测通过；FEAT-070/BUG-139 另已本机 Creo 10 实机验收；待合入 main 并发布）

目标版本：0.34.0

来源与关联：0.31.1 反馈「上轮两项反馈跨 6 版本未修」第二项；归档见 [feedback-0.31.1-2026-11-20](../validation/feedback-0.31.1-2026-11-20/SOURCE_MANIFEST.json) F01。关联 `tools/test_update_check.py`、`tools/test_model_reconciliation.py`、`docs/UPDATE_CHECK.md`、`tools/dev_check.py` 与 CI。

分类依据：硬编码断言在 0.31.1（实际 109 工具）必失败，且被 `TaskGroup` 异常包装掩盖真实断言；自引入后从未被门禁覆盖，跨 6 版本零改动。

## 问题或目标

`tools/test_update_check.py:108` 仍断言 `capabilities["tool_count"] == len(tools) == 82`，`tools/test_model_reconciliation.py:331` 仍断言 `capability["tool_count"] == 84`；实际 `tool_count=109`（以 `creo_capabilities` 为准）。两处硬编码始于 2026-10-14（FEAT-020，当时 82），此后工具数 82→95→102→104→107→108→109 一路增长，断言从未更新。

更糟的是断言失败被包装成 `unhandled errors in a TaskGroup (1 sub-exception)`，真实断言信息在 stdio 输出中不可见，用户／门禁只看到「失败」。`docs/UPDATE_CHECK.md:3` 仍写「工具总数为 82」，与断言同源过时。

为什么跨版本未暴露：`tools/dev_check.py` 只跑 Ruff/clang-format 与 `tools/test_unit.py`；CI `.github/workflows/checks.yml` 只跑 `tools/check_backlog_counts.py` 与 `tools/dev_check.py`。**二者都不运行 `tools/` 下的独立验收脚本**，因此它们自引入后从未被自动门禁覆盖。

## 范围

包含：

1. `tools/test_update_check.py:108`：去除 `== 82`，改为 `assert capabilities["tool_count"] == len(tools)`，另设与版本解耦的一致性检查（例如 `tool_count` 与实际工具列表长度一致即可，不写死数字）。
2. `tools/test_model_reconciliation.py:331`：去除 `== 84`，同样改为与实际工具数解耦的断言。
3. 两处断言失败不要把原始异常吞进 `TaskGroup`：显式打印／抛出断言上下文，让失败可诊断。
4. `docs/UPDATE_CHECK.md:3`：把「工具总数为 82」改为「以 `creo_capabilities` 返回为准」。
5. 扩大门禁覆盖：在 `tools/dev_check.py`（或 CI）增加一步，至少做 `tools/test_update_check.py`、`tools/test_model_reconciliation.py` 的离线可运行性检查（不依赖 Creo），防止独立验收脚本腐化。

不包含：

- 不改 `creo_capabilities` 本身的工具计数逻辑。
- 不处理 0.31.1 反馈的第一项（单测 teardown），归 [BUG-137](BUG-137.md)。

变更文件：
