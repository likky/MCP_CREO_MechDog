# BUG-139：启动协调器 2 秒探测超时且预算耗尽后丢弃已成功探测，导致全部建模工具拒单

分类：**部分交付 0.34.0**

类型：缺陷

优先级：P1

状态：部分交付 0.34.0（已实现并离线单测通过；FEAT-070/BUG-139 另已本机 Creo 10 实机验收；待合入 main 并发布）

目标版本：0.34.0

来源与关联：0.31.1 反馈「启动校验 2 秒探测超时且预算耗尽后丢弃已成功探测，致 109 个建模工具全部拒单」；归档见 [feedback-0.31.1-2026-11-20](../validation/feedback-0.31.1-2026-11-20/SOURCE_MANIFEST.json) F02。关联 `creo_startup.py`、`bridge.py`（`session_status`／`record_channel_health`）、`build/toolkit_health.json`。

分类依据：本机 Creo 9 连续 4 轮实机复现——`creo_session_status` 同时返回 `connected:true`，但协调器仍发布 `timeout`，`require_ready()` 永久拒绝一切建模作业；根因与代码位置已定位到 `creo_startup.py`。

## 问题或目标

启动协调器在**原生 worker 与 Creo 都已就绪、独立探测 `connected:true`** 的情况下，用**硬编码 2 秒连接超时**反复探测，永远拿不到成功；300 秒总预算耗尽后，即便最后一轮探测已经成功，也**只发布 `timeout`、不发布 `ready`**，于是 `require_ready()` 永久拒绝一切建模作业（109 个工具全部不可用，包括 `creo_new_part` 与 `creo_execute_plan`）。

已定位的具体缺陷：

1. **探测超时硬编码 2 秒且一次即判死**：`creo_startup.py` 连接循环内 `bridge.session_status(connect_timeout_seconds=2, build_worker=False)`（当前 `:757`／`:986`／`:1216` 三处）。本机 Toolkit 异步握手耗时在 2 s 与 9 s 之间：9 s 成功、2 s 永久失败；`bridge.session_status()` 对 `probe_timeout` 直接返回不重试。
2. **预算耗尽后成功探测被丢弃**：连接循环的 `if native.get("connected")` 判定在循环体内（当前 `:1235`），循环条件先因 `deadline` 到期失败 → 不再执行循环体的成功判定 → 即使上一轮 `native.connected` 已为 `true` 仍发布 `timeout`（返回体里 `state:"timeout"` 与 `native.connected:true` 并存）。
3. **连接阶段无独立相位**：`build_native()` 返回后没有任何状态更新，整个连接阶段（最长 300 秒）对外仍显示 `building_worker`，`updated_at` 冻结在周期起点，`phase_remaining_budget_seconds` 与真实进度脱节。
4. **总预算固定 300 秒**：冷启动 Creo（6–8 分钟）与 300 秒预算天然冲突；`preparation` 与 `connect` 共用同一个 deadline。
5. **无准入降级**：`require_ready()` 不参考「最近 N 秒 `creo_session_status` 是否返回过 `connected:true`」，没有 `force_ready` 操作员覆盖，造成「探测通过但准入不开」的死局。
6. **身份证据不可归因**：`build/toolkit_health.json` 的 `worker_build_identity` 长期保留陈旧的 `invalid_build_info`／`worker_exit_code=3221225781`（`STATUS_DLL_NOT_FOUND`），无 `observed_at`、无产生它的探测环境标识，且与当前 `verified`／`0` 并存，会把人引向错误根因。
7. **错误文案误导**：`"Creo is not ready (building_worker)"` 在构建早已结束时仍然出现，不带最后一次探测的 `toolkit_code`／`connect_timeout`。

## 范围

包含：

1. 探测超时可配置（如 `creo_probe_timeout_seconds`，默认 ≥ 10），`probe_timeout` 在预算内重试而非一次判死。
2. 成功探测必须能落地：把 `connected` 判定移到循环之外（循环结束后再判一次），或「预算耗尽前最后一次探测成功 → `ready`」。
3. `build_native()` 返回后立即 `publish("connecting", ...)`，并让 `updated_at` 随每次探测刷新。
4. 总预算自适应／可配（`startup_total_budget_seconds`），准备与连接分段计时。
5. 准入降级：最近 N 秒 `creo_session_status` 返回过 `connected:true` 时 `require_ready()` 放行，或提供 `creo_startup_status(force_ready=true)` 操作员覆盖。
6. `worker_build_identity` 增加 `observed_at` 与 `env_fingerprint`（至少 PATH 哈希）；`identity_status=verified` 后不再并列展示历史失败码。
7. 错误文案附上「最后一次探测的 `toolkit_code`／`connect_timeout`」。
8. 回归单测覆盖：超时可配、循环外成功落地、相位推进、recent-connected 降级、`force_ready`、陈旧身份清理。

不包含：

- 不改 Toolkit 单通道、busy 立即拒绝、revision 保护等既有边界。
- 不自动重试建模作业；准入打开后仍由调用方提交。
- 不在本卡内做 WorkBuddy 黑盒验收。

## 实现与证据

源码身份：分支 `codex/feedback-0311-0320-feat070`，基于 main `95852899d893f590c6ef37a3724ac669ca7c845e`，`dirty=true`（未提交）。

变更文件：`creo_startup.py`、`bridge.py`、`src/creo_mechdog/...`（启动协调器与 `session_status`/`record_channel_health`）、`config.example.json`、`tests/test_creo_startup.py`、`tests/unit/test_dev_check_timeout.py`。

实现要点（7 项）：
1. 探测超时可配（`creo_probe_timeout_seconds`，默认 ≥10），`probe_timeout` 在预算内重试而非一次判死。
2. 成功探测落地在循环外：循环结束后再判一次 `connected`，预算耗尽前最后一次成功探测仍能发布 `ready`。
3. `build_native()` 返回后立即 `publish("connecting", ...)`，`updated_at` 随每次探测刷新。
4. 总预算可配（`startup_total_budget_seconds`），准备与连接分段计时。
5. 准入降级：最近 N 秒 `creo_session_status` 返回过 `connected:true` 时 `require_ready()` 放行，或 `creo_startup_status(force_ready=true)` 操作员覆盖。
6. `worker_build_identity` 增加 `observed_at` 与 `env_fingerprint`；`identity_status=verified` 后清除并列的陈旧失败码（`invalid_build_info`/`worker_exit_code`）。
7. 拒绝文案附上最后一次探测的 `toolkit_code` 与 `connect_timeout_seconds`。

离线：26 项定向单测覆盖超时可配、循环外成功落地、相位推进、预算分段、recent-connected 降级、`force_ready`、陈旧身份清理与文案，全部通过；`ruff check`/`ruff format --check` 通过。

实机（本机 Creo 10.0.0.0 / release 42，2026-11-19 常设授权）：冷启动——结束 xtop 与 nmsd 进程、确认无残留 `creo_worker` 后清理 `toolkit.lock`，启动协调器从冷态走到 `ready`（不再在 `connected:true` 时发 `timeout`），随后 FEAT-070 建模作业成功并保存重载（见 FEAT-070 卡）。

未测范围（如实记录，不外推通过）：`force_ready` 降级路径与失败路径文案未在本机 Creo 10 构造实机夹具复现（由 26 项单测覆盖）；Creo 12.4 / Creo 9、WorkBuddy 黑盒未验。
