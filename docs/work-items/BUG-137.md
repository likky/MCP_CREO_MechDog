# BUG-137：全量单测 teardown 因 `subprocess.Popen` 未隔离报 WinError 32，发布口径与真实复验不一致

分类：**部分交付 0.34.0**

类型：缺陷

优先级：P1

状态：部分交付 0.34.0（已实现并离线单测通过；FEAT-070/BUG-139 另已本机 Creo 10 实机验收；待合入 main 并发布）

目标版本：0.34.0

来源与关联：0.31.1 反馈「上轮两项反馈跨 6 版本未修，全量单测仍 3 errors」；归档见 [feedback-0.31.1-2026-11-20](../validation/feedback-0.31.1-2026-11-20/SOURCE_MANIFEST.json) F01。关联 `tools/test_unit.py`、`bridge.py`、`tests/unit/test_inspection_only_admission.py` 与发布记录口径。

分类依据：已在 0.31.1／0.32.0 逐字复现，根因定位到测试未 patch `Popen` 与 `bridge.py` 真实子进程继承 `runner.log` 句柄，跨 6 版本未修。

## 问题或目标

全量 `unittest`（`tools/test_unit.py`）在本机为 **4078 项 / 0 failures / 3 errors / 退出码 1（`success=false`）**，3 个错误全部在 `InspectionOnlyAdmission` 的 teardown：`TemporaryDirectory` 清理 `runner.log` 时 `PermissionError: [WinError 32] 另一个程序正在使用此文件`。测试逻辑已通过，失败在清理阶段。

根因：

- `bridge.py` 的 worker 启动用真实 `subprocess.Popen`（当前 `bridge.py:1689`），并把 `runner.log` 以 `ab` 打开传给子进程 `stdout/stderr`，子进程继承该文件句柄。
- `tests/unit/test_inspection_only_admission.py` 的 `run_job()` 只 patch 了 `bridge.subprocess.run`（synthetic worker），**没有 patch `subprocess.Popen`**，于是真实 `Popen` 启动的 worker 在测试清理临时目录时尚未退出，`runner.log` 句柄未释放。单跑该类可通过但带 `ResourceWarning: subprocess ... is still running`，只在全量时序竞态下命中。

同时发布记录（如 `RELEASE-0.31.1.md`）写「全量 unittest 4078 项通过（6 跳过）」，与本机 3 errors / 4 skipped 不一致；发布口径未要求 `success=true`。

## 范围

包含：

1. `tests/unit/test_inspection_only_admission.py`：patch `subprocess.Popen`（或让 `bridge.py` 的 worker 启动走可注入工厂），使测试不启动真实子进程；或在 `run_job` 后 `proc.wait()` 确保子进程退出再离开 `TemporaryDirectory`。
2. 发布口径：生成／校验发布记录的脚本应要求 `tools/test_unit.py` 报告 `success=true` 才能写「全量通过」，并同时列出 `failures`／`errors`／`skipped` 的真实数字。
3. 回归用例：覆盖不启动真实 `Popen` 的 teardown 清理成功。

不包含：

- 不改 `bridge.py` 生产路径的真实 worker 启动行为本身，只隔离测试。
- 不处理 0.31.1 反馈的第二项（硬编码工具数），归 [BUG-138](BUG-138.md)。

## 实现与证据

源码身份：分支 `codex/feedback-0311-0320-feat070`，基于 main `95852899d893f590c6ef37a3724ac669ca7c845e`，`dirty=true`（未提交）。纯离线，无原生改动、未启动 Creo。
