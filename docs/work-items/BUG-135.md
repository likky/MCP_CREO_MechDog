# BUG-135：element_tree 路线 ProFeatureElemtreeExtract 返回 -18 时作业直接回滚，无法保留已建特征

分类：**部分交付 0.33.0**（`accept_unverified_completion` 旁路已可控；本机 Creo 10 内核无法补全几何，作业明确失败并清理；Creo 12.4 成功路径未验）。

类型：缺陷

优先级：P2

状态：待验收（2026-11-20 本机 Creo 10 实机：旁路已可控，但内核无法补全几何，作业明确失败并清理；Creo 12.4 成功路径未验）

目标版本：0.33.0（候选）

来源与关联：0.31.1 反馈“Arm7 / 装配 0.31.1 复测”中 element_tree 放样 `create_code=0` 但提取返回 -18；关联 FEAT-065、[BUG-120](BUG-120.md)、[BUG-134](BUG-134.md)。

分类依据：待验收——Creo 10 上 `accept_unverified_completion` 已能保留并检查特征，但该宿主的 `ProFeatureWithoptionsRedefine` 与 `ProSolidRegenerate` 都无法补全特征，`ProFeatureIsIncomplete` 恒为 true、quilt 为 0；因此“作业 succeeded、面积/开闭可测”的原始验收行在 Creo 10 不可能达成，Creo 12.4 成功路径仍未执行。

## 问题或目标

Creo 10 上 element_tree 路线的放样特征已创建成功（`create_code=0`），但随后 `ProFeatureElemtreeExtract` 返回 -18（`PRO_TK_INVALID_TYPE`，该特征类型不支持提取）。代码无条件抛错并回滚，用户拿不到已经生成的几何；反馈建议保留一条可控的旁路。

## 范围

1. `native/surface_loft.cpp` 的 -18 分支改为按 `tree_available` 判断，不再无条件失败。
2. 新增显式选项 `accept_unverified_completion`（默认 `None`，经 `exclude_none=True` 序列化，不改变旧计划字节）。仅当调用方显式接受、且无 `boundary_conditions`、无 `template` 时允许继续：`accept_unverified = op.value("accept_unverified_completion", false) && conditions.empty() && !template_tree`。
3. 提取失败时追加三次补全尝试，结果全部写入回执：`ProFeatureElemtreeCreate`（旧入口，`extract_create_code`）、用创建树 `ProFeatureWithoptionsRedefine`（`accept_redefine_code` / `accept_redefine_element_errors`）、`ProSolidRegenerate` + `ProFeatureIsIncomplete` 复核（`accept_regenerate_code` / `feature_incomplete_after_regenerate`）。
4. 接受时回执写 `completion_verified_by="geometry"`、`completion_unverified_reason="element_tree_extract_unsupported"`，继续执行状态、quilt、面积与开闭验证；三次补全后仍 `feature_incomplete=true` 时以 `SURFACE_LOFT_ACCEPT_INCOMPLETE` 失败并回滚，不再把空特征当成功。
5. `src/creo_mechdog/surface_ops.py` 新增字段与校验器 `unverified_completion_needs_no_tree_consumers`：panel 路线、`boundary_conditions`、`template` 一律拒绝。
6. `src/creo_mechdog/capabilities.py` 的 `require_kernel_completion` 对整组显式接受放行。
7. `src/creo_mechdog/job_projection.py` 的 `SURFACE_LOFT_KEYS` 增加 `completion_verified_by`、`completion_unverified_reason`。
8. `server.py` 新增公开参数 `accept_unverified_completion: bool = False`。
9. 不包含：不改变 element_tree 提取本身，不放宽 panel 路线或带模板/边界条件的计划，不猜测缺失的树元素。

## 验收标准

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| Windows / Python | `.\.venv\Scripts\python.exe -m unittest tests.unit.test_surface_loft_schema tests.unit.test_surface_loft_kernel_admission tests.unit.test_surface_loft_panel_schema -q` | 三组单测通过；默认计划字节不变；panel / 模板 / 边界条件带该参数被拒 |
| 本机 Creo 12.4 | element_tree 放样加 `accept_unverified_completion=true` | 作业 `succeeded`，回执标注 `completion_verified_by="geometry"` 与原因，quilt 面积与开闭可测，`saved_file_reloaded_and_verified=true`；未复测 |
| 本机 Creo 10.0.0.0 / release 42 | 同上 | 实测：`extract_code=-18`、`extract_create_code=-18`、`accept_redefine_code=-1`、`accept_regenerate_code=0`、`feature_incomplete_after_regenerate=true` → `SURFACE_LOFT_ACCEPT_INCOMPLETE`，作业 failed，新模型清理 `absence_verified=true` |
| 本机 Creo 10.0.0.0 | 不加该参数提交同一计划 | 行为不变，仍在 -18 处抛 `SURFACE_LOFT_EXTRACT_UNSUPPORTED` 并回滚 |

Creo 10 判定：该宿主内核既拒绝元素树回读，也拒绝用创建树补全，element_tree 放样只能走 resident_panel 路线；`accept_unverified_completion` 在 Creo 10 上是“保留并如实检查、失败即回滚”的旁路，不是成功捷径。Creo 12.4 的行为不得据此外推。

## 实现与证据

变更文件：`native/surface_loft.cpp`、`src/creo_mechdog/surface_ops.py`、`src/creo_mechdog/capabilities.py`、`src/creo_mechdog/job_projection.py`、`server.py`。

离线证据（2026-11-20）：全量单测 4156 项通过、6 项跳过；Ruff `All checks passed`；`bridge.py build` 退出码 0。离线只覆盖 schema 准入、默认字节不变与投影字段。

**Creo 10 实机（2026-11-20，本机 `Creo 10.0.0.0` / `release_numeric=42`）**：

- 接受路径：作业 `21535fea4d0f408bb74c2a0ccc08a99d`（模型 `acc_tree_20261120g`）失败，错误
  `surface_loft created the blend (create_code=0) but this Creo release refused its element tree (code -18), the redefine with the creation tree failed (code -1) and regeneration left feature_incomplete=true (SURFACE_LOFT_ACCEPT_INCOMPLETE); the retained feature owns no geometry and the job was rolled back; use the resident_panel route on this release`。
- 回执字段：`extract_code=-18`、`extract_create_code=-18`、`extract_api=ProFeatureElemtreeExtract`、`accept_redefine_code=-1`、`accept_redefine_element_errors=0`、`accept_regenerate_code=0`、`feature_incomplete_after_regenerate=true`、`quilt_count=0`；清理证据 `failed_model_cleanup={status:erased,absence_verified:true}`。
- 基线（不加参数）：同样 `-18` 处失败并回滚，回执 `kernel_completion="unsupported"`。
- 结论：Creo 10 的“保留件再生”只能做到保留与如实报告，几何由内核拒绝补全；同一宿主的 resident_panel 路线成功（见 [BUG-134](BUG-134.md)）。

未验：Creo 12.4 成功路径、Creo 9、WorkBuddy 黑盒、`accept_unverified_completion` 在 12.4 上与 panel 准入组合。
