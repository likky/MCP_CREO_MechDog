类型：缺陷

目标版本：0.35.0（子项已交付）；0.35.1（根因修复已交付）；0.35.5（真实 disconnect 阻塞验收）

## 问题或目标

0.32.0 证据显示失败计划已回滚成功，worker 在 `PHASE=disconnect` 以 `0xC0000409` 退出，最终 `native_result.json` 未发布，作业转 `unknown_outcome` 并预留模型。需先在当前源码核对 disconnect 与结果发布顺序、复现或用最小原生夹具定位崩溃，不能把 try/catch 当作栈 cookie 异常的修复。无论崩溃根因能否在当前环境复现，执行与回滚结论都应在进入不可逆 disconnect 前形成可恢复的持久化事实，同时保留进程退出异常信号，不伪报正常成功。

## 范围

包含结果交付顺序、崩溃前后状态可恢复性、最小原生/单元回归；若证据支持则包含 disconnect 资源释放最小修复。不放宽 revision、unknown_outcome 或人工恢复保护，不删除原始证据，不把部分操作回执当作已提交几何。

## 实现与证据

2026-11-21 分两部分处理，崩溃根因与结果持久化分开记录：

- **实机复现**：本机 Creo 10.0.0.0 上，`merged_closed_plan` 因 merge 标签 `ProFeatureGeomitemVisit -4` 失败后，worker 在 `PHASE=disconnect` 以 `0xC0000409` 退出（作业 `0e5ea74cb55146979679d6b59f6e779b`），只留下 0 字节 `native_result.json.tmp`，作业转 `unknown_outcome`。退出码与 0.32.0 反馈一致；根因定位与修复见下方开发分支补充。
- **结果交付顺序**：新增 `native/worker_result_delivery.h`，在不可逆 disconnect 前把执行/回滚事实写入 `native_result.json`（`delivery_complete=false`、`completion_stage="before_disconnect"`、`disconnect_code=null`），disconnect 正常返回后再发布完整终态；`native/worker.cpp` 的 generic/drawing/plate 出口统一走该包装。
- **非 UTF-8 文本**：`native/result_delivery.h` 的发布改用 `dump(..., error_handler_t::replace)`。复现时的 0 字节临时文件与 Toolkit 错误文本中的非 UTF-8 字节吻合，原默认 handler 会抛异常中断发布；替换后回执可写。根因见下方开发分支补充（MSVC 缺少 `/utf-8`）。
- **保护不变**：`delivery_complete=false` 或缺事实时 Python 仍判 `unknown_outcome`，revision、`pending_job`、人工恢复保护不变（`bridge.py`/`generic_bridge.py`/`reconciliation.py` 既有判定）。
- **证据**：新增 `tests/native/test_bug142_result_delivery.cpp` 与 `tests/unit/test_bug142_result_delivery.py`（注入 `0xC0000409`、看门狗退出 31、正常失败/成功三类）；专项 7 项、组合回归 35 项、全量 4286 项通过。实机失败路径（作业 `975f8b2ce81b4079b68485b66eeeb718`，开放 quilt 拒绝）`native_result.json` 存在、`delivery_complete=true`、`rollback_succeeded=false`、无残留 `.tmp`。

未验证：崩溃栈 Cookie 的根本触发点；0.32.0 现场的原始模型；真实 disconnect 阻塞（看门狗路径仅原生夹具注入）。

## 开发分支补充：根因定位（0.35.0 之后，未发布）

- **根因证据链**：实机崩溃日志 `jobs/0e5ea74c…/native.log` 中 `BUILD_FAILED` 行的原始字节为 `… instead \xe2\x80?its label …`——UTF-8 弯引号/破折号 `E2 80 94` 被第三字节替换为 `?`，形成非法 UTF-8。发布前构建命令没有 `/utf-8`，MSVC 按系统代码页（CP936）解读窄字符串字面量，把非 ASCII 字符写成了非法字节。
- **崩溃机制**：`publish_native_json` 用 `json.dump(2)` 的严格 handler 序列化回执；遇到非法 UTF-8 抛 `type_error`，未捕获异常 → `terminate`/`abort`，Windows 呈现为 `0xC0000409`，而 `ofstream` 已创建 0 字节临时文件——与实机留下的 0 字节 `native_result.json.tmp` 完全一致。
- **对照复现**（`tests/native/test_bug142_result_delivery.cpp` 新增 `strict_dump_crash`/`invalid_utf8`/`invalid_utf8_complete`）：严格 `dump()` + 非法字节 → 退出码 `0xC0000409`、留下 0 字节文件；替换 handler 下同一回执可发布（失败码 30、成功码 0），`delivery_complete=true`、无残留 `.tmp`。
- **修复**：`bridge.py` 三条 `cl` 构建命令加入 `/utf-8`，并把 `NATIVE_BUILD_FLAGS /utf-8-v1` 纳入构建指纹，避免旧缓存静默复用未按 UTF-8 编译的 worker。强制重编译后 `build/creo_worker.exe` 中弯破折号字节由 `E2 80 3F` 变为合法的 `E2 80 94`。
- 回归：`tests/unit/test_bug142_result_delivery.py` 新增 4 项（含构建命令 `/utf-8` 断言与崩溃签名复现）；定向 11 项通过。

仍未验证：0.32.0 现场原始模型与本机之外的 Toolchain；真实 disconnect 阻塞路径；`Publish` 之外是否还有其他非法字节来源（替换 handler 已兜底）。

## 开发分支补充：0.35.1 下等价复演（2026-11-21，未发布）

- **原现场不可逐字复演**：0.32.0 的模型目录（`E:\WorkBuddy Space\MCP MCP_CREO_MechDog`、`models/f6ac…`）已不存在，只剩桌面反馈归档里的 `job.json`、计划与 `native.log`；因此用同形链复演，不伪造原模型结论。
- **等价链**：`sketch → fill → sketch → fill → quilt_merge(label=replay_merged) → solidify(reference {kind:"quilt_feature",label:"replay_merged"})`，脚本 `build/live_probe_bug142_bug143.py`，证据 `build/live_probe_bug142_bug143.json`。
- **结果**：`solidify` 正常解析标签并拒绝几何——`solidify requires a closed quilt; the referenced quilt is open (ProQuiltVolumeEval=-18, quilt_is_open)`；不再出现 `ProError -4 … could not be read for quilt geometry`，Creo 主线程未崩溃；`native.log` 为合法 UTF-8（U+FFFD 计数 0），`native_result.json` 存在、`delivery_complete=true`、`completion_stage="result_delivery"`。
- **结论**：0.35.1 的标签解析与失败发布路径成立；0.32.0 的 `-4` 来自该现场 quilt 自身的几何读取，而非标签解析，原始字节链已无模型可核。仍不能据此宣称原崩溃栈 100% 复现。

## 0.35.5：真实 disconnect 阻塞路径实机核验（2026-11-21）

- **测试钩子**：`native/result_delivery.h` 在预断开 checkpoint 落盘之后、`ProEngineerDisconnect` 之前支持环境变量 `MECHDOG_TEST_DISCONNECT_DELAY_MS` 休眠（上限 60000 ms，默认关闭，仅用于在实机会话中撑开该窗口）。`tests/native/test_bug142_result_delivery.cpp` 新增 `delay` 模式，`tests/unit/test_bug142_result_delivery.py` 新增用例断言耗时 ≥ 0.04 s、stderr 含 `TEST_DISCONNECT_DELAY_MS=40`、断开观察时 checkpoint 与预发布 `native_result.json` 均存在且 `delivery_complete=false`，最终 `completion_stage="result_delivery"`。
- **实机**（本机 Creo 10.0.0.0 / release 42，`build/live_bug142_disconnect.py`，证据 `build/bug142_live_disconnect.json`）：作业 `9a73ad5e6a50466c8b4c2d3fdf6fc583` 在延迟窗口内已写出预发布 `native_result.json`（`delivery_complete=false`、`completion_stage="before_disconnect"`、`success=true`、`saved_file_reloaded_and_verified=true`，无 `.tmp`）；对 worker pid 25844 发 `SIGTERM` 后，作业转 `unknown_outcome`，消息 “Native finalization was not confirmed; preserve saved files and inspect the checkpoint”，模型 `status="unknown_outcome"`、`revision=0`、`pending_job=9a73ad5e…`；事后 `native_result.json` 仍为 `delivery_complete=false`、无残留 `.tmp`。
- **对照组**：随后作业 `8d84a22553f14c5583338b7330cd1959` `succeeded`，说明结束 worker 后会话仍可用，`unknown_outcome` 不是会话失效。
- **结论**：被中断的 disconnect 不再抹掉执行/回滚事实，也不被投影为成功；保护按 `delivery_complete=false` 维持 `unknown_outcome`。真实阻塞路径的实机验收闭环。未验：其他 Creo 版本、WorkBuddy 黑盒与 0.32.0 原模型。
