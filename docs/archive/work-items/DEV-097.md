目标版本：0.34.0

来源与关联：0.32.0 反馈「上一版提交号门禁盲点四版未修复」P2；归档见 [feedback-0.32.0-2026-11-20](../../validation/feedback-0.32.0-2026-11-20/SOURCE_MANIFEST.json) F01。关联 [DEV-096](../work-items/DEV-096.md)（同反馈 P1，已在 0.33.0 修复）、`tools/check_release_assets.py`、Release 正文生成流程。

## 问题或目标

0.32.0 的 GitHub Release 正文不再列任何 SHA256、附件名，也不再写「摘要在 sidecar」；而 `RELEASE-0.32.0.md` 与 POSTCHECK 段都写清楚了摘要在 sidecar。用户仅看 Release 页面时，无法从正文得知摘要位置。

门禁为什么没发现：`tools/check_release_assets.py` 只下载／校验四附件与 sidecar，没有读取或检查 Release body；本轮远端 `--tag` 仍 `exit 0`。这不代表资产损坏（本地、sidecar、API digest 都一致），只是正文自证缺口没有自动化覆盖。

## 范围

包含：

1. `tools/check_release_assets.py`：增加 Release body 检查——正文至少列出四个附件名，并存在「源码包摘要记录在同名 sidecar 中」之类明确指引；若正文列了摘要值，则从 body 提取后与 sidecar 实值比较，不一致即失败。
2. Release 正文生成流程：定位生成 Release body 的脚本／模板，保证正文列四附件名 + sidecar 指引（与 `RELEASE-<version>.md` 口径一致），避免只在包内写清楚而 Release 正文缺失。
3. 回归用例：body 缺附件名／缺 sidecar 指引 → 失败；齐全 → 通过；body 摘要值与 sidecar 不一致 → 失败。
4. 对现有 0.33.0 Release 实跑一次，确认门禁在正文齐全时通过、不出现误报。

不包含：

- 不改附件与 sidecar 的生成／校验逻辑本身（DEV-096 已覆盖 `previous_release_commit` 交叉校验）。
- 不回填历史 Release 的正文（历史记录逐字节保留，不改写）。
